## 阻断原因

1. Candidate14 Prompt 对没有当前任务的来源要求信息 scope 全部进入 `informationScopeIds`；5.5 评分器却只允许 `kind=information` 的 scope 出现在该数组。包含事件、时间或地点的合规输出可能被扣分。合法 wire oracle 使用了更窄的投影，不能证明模型按 Prompt 行事时可得满分。
2. 5.5 对独立事件时间只比较 `rawText` 和 scope，没有核验类型、归一化值、精度、全天标记、是否需确认。审计员用 R5 S09 构造了实际反例：保留正确的“10月3日晚上6点”和 scope，却把类型改成 `event_end`、归一化值改成 `1900-01-01T00:00`、时区改成 `UTC`、`isAllDay=true`、`precision=vague`，评分仍为 `complete=true / major=0`。因此不能用 5.5 判断整份来源的时间正确性。
3. R5 S07 把“不可合并到同一压缩包”直接归入两项任务的完成标准，可能把包装限制错当成独立办结条件；R5 S12 对“提交时间月底另行通知”只记信息 scope，未明确登记未知时间的可表达和评分口径。这是单作者语义裁决，不能为了通过 oracle 就视为真值。
4. 当前 wire 只有信息 scope，没有禁止、引用、待公布的独立语义类别。5.5 对这些事实只能证明原文范围被保留，不能证明模型正确理解其性质；因此相关准确率不得宣称已验证。

## 下一轮必须先做的事

先建立一张 Prompt 要求、wire 字段、公共 adapter、参照字段、评分规则、确认页处置的逐项对应表。对无任务事件及其时间构造至少一份合法正确 wire 和相反语义 wire，要求前者走公共链路得完整分，后者明确失败；信息 scope 的允许集合须与 Prompt 一致。把材料格式/包装限制和可验证完成标准分开裁决。无法由当前 wire 表达的语义标为未观测，不补造分数。合同和门槛经独立审计通过后重新冻结并推送，然后另造全新来源；R4/R5 文本均纳入逐字与高相似排除。不得复用 R5 身份或先前任何模型调用许可。
