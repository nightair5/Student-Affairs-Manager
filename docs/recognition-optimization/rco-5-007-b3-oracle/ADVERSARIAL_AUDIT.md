## 第一性原理诊断

P1 的目标不是猜关键词，而是把每条原文命题稳定映射成五个责任不同的判断：谁要做、现在是否要做、做什么对象、动作有什么外部效果、是否可安全默认勾选。本次失败不是一个分数小波动，而是三处责任层仍由容易冲突的词法规则代替了语义判断。

1. **条件事实仍按否定字面匹配**：B3-06 的“无法闭合”既是条件内容，也是明确发生的事实；P1 因看到“无”把触发事实当成否定，导致唯一的 `requiresAction` 错误。说明条件闭环必须比较完整命题的肯定/否定关系，不能扫描单字。
2. **动作表面词被本机词典重写**：B3-10 的理想锚点明确给出动作“办理”、对象“线上缴费”、类型 `pay`，P1 却把原文里的“缴费”升级成动作，破坏动作逐字保真并造成 1 FP + 1 FN。受控类型可以修正风险类别，但不能替换已验证的原文动作锚点。
3. **主体与修订状态仍受邻近词污染**：B3-03 因动作前出现对象“成员名单”而把执行者误改成群体；B3-01 能识别旧要求已作废，却没有稳定还原旧命令的时态/极性。主体必须来自句法角色或独立证据，而不是动作前任意出现“成员”；修订状态与原命令时态也应分层表达。
4. **参考标签存在一处可疑口径，但不改变失败结论**：B3-04 把“正式成员请填写”标为必做群体动作，却未标为默认勾选；P1 按冻结安全规则选择了它，造成整例失败。这是单作者 Expected 的口径歧义，不能冻结后改答案。本轮仍按原分母报告。即使把该例从敏感性分析中视为标签争议，Complete Case 也仅 12/16=75%，仍低于 80%；`requiresAction` 仍为 15/16=93.75%，仍低于 95%。

## 主线含义

P1 的安全底线有效：25 个参考指令中没有产生危险默认操作，安全默认 Recall 为 100%。但商业主线要求“完整任务少改”，而不是只要求“不误点”。当前 5/16 案例需要重要修改，整例正确率 68.75%，因此在理想上游输入下本机层仍是瓶颈；此时付费测模型只会把上游错误叠加在已知本机错误之上，不能回答是否值得上线。
