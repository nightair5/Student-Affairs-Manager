# RCO-5-007-B7-M1 对抗审查

## 一句话结论

模型很会找到“要处理什么”，但不稳定地把“请、须、不得、可自行、要求是”等语气词一起塞进动作字段；冻结 P3 恰好依赖动作前面的语气词判断必做、可选和禁止，二者接口错位后会产生真实安全错误。因此本轮不值得接入稳定路径，也不应立刻用更多付费调用追分。

## 模型真正做对了什么

- 12/12 请求都有明确回执，12/12 通过严格 JSON Schema 和来源绑定。
- 12 个案例的行动条数全部正确，共找到 18/18 个行动；没有把引语中的演示命令当成真实任务。
- 对象逐字完全正确 18/18。
- 期望的核心动作词在模型 action 中全部出现 18/18；但严格动作边界只对 8/18。
- scope micro F1 为 95.2%，没有多挂 scope，但漏挂了 2 个条件事实 scope。
- 没有模型输出 `selected`、语义、风险、修订关系或 Expected 泄漏；模型权限边界有效。

以上“核心动作词 18/18”是运行后的诊断指标，不是预注册过门指标，不能替换 44.4% 的严格动作完全正确率。

## 失败的主因

10 个动作边界错误全部属于同一类：模型返回的是完整谓语片段，而冻结 Expected 要求最小动作词。

| 原文类型 | 模型 action | 期望 action |
|---|---|---|
| 礼貌命令 | `请保存`、`请填写`、`请核对` | `保存`、`填写`、`核对` |
| 强制要求 | `须发送`、`要求上传`、`要求是保存` | `发送`、`上传`、`保存` |
| 可选动作 | `可自行携带` | `携带` |
| 禁止动作 | `不得邮寄` | `邮寄` |

这不是单纯“少了几个正则”。根因是契约把两个不同概念混在一个字段里：

1. 模型把 action 理解成“行动短语”。
2. P3 把 action 理解成“最小动作头”，并只在 action 前方找否定、可选和强制标记。
3. Schema 只检查 action 是 scope 的逐字子串，无法判断它是否吞掉语气标记。

因此格式仍然 12/12 合法，但含义已经错位。

## 三个高风险反例

1. `若器材标签仍未贴齐……当前器材标签仍未贴齐`：模型找到“联系仓储员”，却没有把证明条件已经发生的最后一句挂到同一命题。P3 只能判成条件未知，导致唯一一次 `requiresAction` 错误。
2. `资料夹可自行携带`：模型把 `可自行` 吞进 action，P3 在 action 前找不到可选标记，于是误判为必做并默认勾选。这是实质性安全失败；`Forbidden=0` 没抓到它，是因为本集 forbidden 列表只覆盖特定禁选短语，Complete Case 和默认状态不匹配才把它拦住。
3. `不得邮寄纸质回执`：模型把 `不得` 吞进 action，P3 错判为肯定要求。该例恰好因为“邮寄”属于外部传输而没有默认勾选，但如果同样问题出现在 `不得保存` 这类本地动作上，现有策略可能错误勾选，不能靠这次侥幸当安全证明。

## 对评分器的审查

- 预注册结论 `NO_PROMOTION` 有效，不能在看过结果后放宽门槛。
- Task F1 44.4% 主要是严格对齐要求 action 与 object 同时逐字匹配；10 个扩大动作短语因此按整项错算。它正确反映“输出还需要用户改”，但不等于模型漏掉了 55.6% 的行动。
- cancels 和 supersedes 显示 0%，主要因为报告把 P3 的内部 task ID 映射回 Expected ID 时也依赖动作逐字相等。P3 实际生成了相应关系，但映射结果为 `null`。这两项仍按冻结规则判失败，但不能误解为关系解析器完全没工作。
- `Forbidden=0` 不能单独证明安全；B7-09 已出现可选任务被默认勾选。后续必须单列“任何 expectedDefaultSelected=false 却被 selected=true”的假阳性率。

## 第一性原理判断

产品需要的不是“模型写出漂亮 JSON”，而是：找到真实行动、保留对象、正确理解条件与禁令，并且只把有充分证据的安全任务默认勾选。本轮前两项已经接近可用，后两项仍有会误导用户的失败，所以不能上线。

## 下一步主线

建议下一轮先做 0 次模型调用的 `RCO-5-008`，不要马上付费：

1. 将动作拆成“本机确定的受控动作头”和“原文完整谓语片段”。模型只选 scope、对象及可选的动作候选；本机从受控校园动作表取最小动作头，任何语气词不得进入动作头。
2. P3 的否定、可选、强制判断改为读取完整命题，而不是依赖 action 前缀；即使模型动作边界扩大，也不能改变安全语义。
3. 条件事实由本机按相邻 scope、完整命题和确定性归一化规则自动归属，模型漏挂当前事实时也能得到可审计的条件真值；多候选时保持未知。
4. 关系评分用不可变 scope/内部 relation ID 对齐，不再借动作字符串映射；动作边界错误和关系错误分别计分。
5. 增加“禁止默认勾选假阳性”硬指标，覆盖可选、否定、已完成、已取消、第三人动作和条件未满足。
6. 只在已见 B7 上做 0 调用回归并把上述三类反例全部锁成测试；通过后冻结全新 B8，才申请下一轮付费盲测。

本报告不修改 B7 Expected、freeze、dataset、checkpoint、contract、P3 或 cache，不重算预注册判定，不接稳定路径、不启动 RCO-6、不部署。
