## 3. 方案与必须明确批准的数据边界

### 3.1 重用，不造第二套语义系统

- MAINLINE04 的 SemanticInput、ReviewPackage、composeSemantics、scope/time类型全部只读复用。
- AI/历史候选仍只提来源约束语义；本包只用已有人工输入和已见只读诊断，不调用 AI。
- 不从案例编号、中文关键词或 Expected 决定业务选项；人工回放的案例映射只存在工程输入模块，标明不是分类器。
- 已见 B8-01/07/09 仍为不完整候选诊断；不补写未给出的条件/状态/实体来制造正确任务。
- ReviewPackage 原来的 NOT_RUN 标签不覆写；本包用独立验收结果记录实际是否走完 App/保存。

### 3.2 最小隔离持久化：v8容器 + 显式版本扩展（待批准）

选用现有 WorkspaceV8 与真实 canonical repository，不升全局Schema、不新建数据库引擎：
在新 ExtractionDraft.legacyData.mainline05 中保存严格类型化的 **mainline05-semantic-state-1**。

这是一项需要本次白名单确认的**实验持久化格式**，不是把任意 JSON 藏进 legacyData 就宣称通过。它不是现有 v8 原生语义支持，也不承诺普通入口可导入或消费。

扩展仅包含已有语义数据与产品生命周期信息：
- 来源/版本/Run/Draft身份；原始人工回放文本/对象、适配来源的变化账本和首次语义响应分开保留。
- 复用 SemanticInput，不重新定义条件/状态/修订枚举；不可变scope索引、本机派生引用/时间以及输入身份。
- 用户保存的编辑和明确处置，操作ID/版本；原文与首次建议不可变，选择框不是证据或操作历史。
- 从语义实体ID到canonical实体ID的持久化映射；未确认/暂缓/不适用端点保持明确状态，不能填一个不存在的canonical ID。
- 确认后任务/材料/时间/事件仍存入v8原生数组；它们的legacyData只保存指向该版本化记录的定位信息，不另存可独立改写的第二套任务事实。

semanticState 的联合校验必须覆盖输入版本、原始身份一致性、scope、全部实体/归属、编辑采用、ID映射和生命周期；原v8 validator继续检查原生数组。semanticRepository必须在load、transaction前后、export都运行两层校验，不能允许调用方绕过扩展检查。

真正无截止不新增时间或提醒；只有开始时间不伪造截止；条件未知保留未知；模糊时间和坏引用不是“无日期”。

### 3.3 来源先存与失败恢复

复用 capture.beginCapture 的真实来源链；在新包装事务中把Run身份标为新语义版本并保存后续状态，不让“2.0”错标为本轮格式。旧capture.recognize只服务旧等价路径；新语义不得构造假2.0 result，语义草稿 result=null，由新投影读取显式扩展。

输入来源写入成功后才调用人工响应回调。回调/绑定/组合失败保留来源和明确失败Run/Draft，不写正式任务；坏凭据预检查失败不得新增来源。重复操作必须核对同一来源和输入身份，不能错误复用旧内容。

每个新05库只允许该格式，缺库/坏库/版本不认识即失败，不fallback旧库、不导入真实库、不自动迁移旧05数据。新库初始化和刷新恢复必须区别；刷新不能再次“初始化清空”。

### 3.4 用户确认、部分关系和原子性

- “现在需要做”“允许人工确认”“安全默认选择”“用户实际勾选/点击确认”四者分开；继续遵从MAINLINE04默认策略。
- 条件真且证据/安全有效、新要求生效、普通独立兄弟必须能确认；条件假/未知、作废项不能靠 selected=true 强行确认。
- 暂缓和“不需要”是可持久化处置，不等于否定原文；纯信息可标已核对而不建任务/空项目。余项刷新后可再打开。
- 本包只支持建议名称、可承接的明确截止时间编辑及无日期补日期；保持原文、首次建议、用户编辑分离。planned_start/事件时刻编辑不扩展，保存前明确拒绝，而非保存后忽略。
- 用户编辑保存前使用提交器的同一规则演练；未保存缓冲不能确认。日期/时区在输入、保存、预览、提交、刷新、日历一致。
- 一次面板批量确认在同一事务写完整选中集合；失败全部回滚。收件箱跨草稿批量按草稿事务，明确报告已成功与失败，不伪称跨草稿原子。
- 共享材料/时间/事件只创建一次；原生关联只指向已确认canonical实体，待确认端点完整保留在语义记录并标记待确认。以后确认兄弟时可在同一事务追加关联，不篡改已有属性。
- 真实任务依赖/父子关系不等于共享资产。缺少必须的未确认依赖时明确提示先确认依赖或一并确认；不得自动确认未选任务或删依赖。完全独立兄弟不连坐。
- 本包修订只解释同一来源内旧/新要求并保存两端语义；不会自动取消或覆盖此前已确认任务。跨来源/已确认实体修订保持待人工处置，不宣称已完成跨通知变更。
- 新显式DomainCommitPlan应用入口处理语义草稿状态与语义补丁；原接口/default不改。正式实体+关联+接受状态+本次确认历史+语义映射在同一canonical事务完成。
- 先前单独成功保存的编辑历史在后续确认失败时保留；失败事务本身不留下半笔确认。重复提交幂等，过期标签拒绝覆盖并提供重新加载入口。

### 3.5 下游和回滚

真实任务中心、首页和日历使用新只读视图；详情展示条件、旧/新要求、事件/材料/时间、逐字依据和编辑记录，而非只保留导出文件里的一团JSON。事件只随用户明确预览同意的任务关系一起保存，不自动生成额外任务。

实验开关仅由新回环启动器注入受验证runtime，正常main.tsx不改；公共组件只接受可选props/插槽，缺省保持旧行为。禁止在普通App静态导入语义composer或工程回放。原隔离V2入口照常保留。

新空独立v8库、明确origin/库名；库名使用既有合法前缀 rco-mainline-01-02-i1-mainline05- 加本轮随机ID，不复用既有库。一个验收run固定其回环端口和库名，刷新/第二标签恢复同库；换端口或新run不得冒充原库恢复成功。默认演示、旧localStorage/迁移、模型/OCR/URL网络、通知/权限/外发全部关闭。保留旧库证据。非核心导航由App拒绝；支持范围外编辑/执行/ICS/课程等UI预禁用且处理器也拒绝。

导出必须真实下载文件，文件同时保留v8实体和已验证版本扩展；注明仅05实验格式，禁止导入稳定入口。与独立repository读回全对象比较，记录路径/字节/文件SHA/规范JSON摘要及读库来源；不能自算两次哈希冒充读库。

关闭本机启动器即停止本实验，不迁移用户库、不回滚已确认用户数据。Git回退仅作为后续明确授权的可逆提交操作，不reset/清库。
