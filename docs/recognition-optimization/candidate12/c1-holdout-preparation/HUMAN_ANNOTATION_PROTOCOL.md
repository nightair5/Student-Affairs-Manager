# Candidate12 Holdout 独立人工标注协议

版本：`candidate12-human-protocol-1.0.0`。适用对象：12 份全新匿名校园通知。

## 1. 角色与盲化

- Candidate12 实现者已在提交 `c03368054ff8c357f055658c2d2d39b45bbcb761` 冻结候选，不参与新来源或 Expected 的编写、修改和裁决。
- 标注者 A 与复核者 B 必须是两个不同的真实人员。二者不得查看 Candidate12/candidate03 输出、B1/B2 模型回答、Prompt 教学答案、评分结果或未来运行顺序中的模型结果。
- 二者只接收匿名来源、参照 Schema、评分字段说明和本协议。来源提供者可以与标注者 A 相同，但标注者 A 和复核者 B 必须不同。
- 使用 Codex、ChatGPT、DeepSeek 或其他模型生成、补写或审核参照时，必须声明 `modelAssistanceUsed=true`，truth status 改为 `PROVISIONAL_MODEL_ASSISTED`，整包不能进入独立 Holdout。

## 2. 来源要求

- 必须是 Candidate12 冻结之后才向候选实现者不可见地收集的 12 份新来源；不得改写 B1/B2、历史 Golden、Prompt 教学例或工程夹具来凑数。
- 删除姓名、学号、手机号、邮箱、精确住址、账号、群号和其他可识别信息；占位符必须保持语义角色，但不得保留真实值。
- 每份来源记录出处类型、取得时间、匿名化方式和来源提供者匿名 ID。正文一旦交给标注者即计算 SHA-256，后续修改形成新版本。
- 12 份来源共同覆盖单任务、多任务、true/false/unknown 条件、共享材料、精确时间、模糊时间、完成标准、依赖、禁止项；多端点取消/替代至少 2 份。

## 3. 标注者 A

逐份先列“最小义务清单”，再填写结构化字段：

1. 每个当前或历史端点必须有动作、对象、执行归属和逐字依据。
2. 动作、对象、条件、时间、完成标准、状态或材料归属不同就拆分；仅当这些字段全部一致且仍可逐项计分时才允许合并。
3. 材料记录 required、格式、命名、数量、渠道、就绪事实和任务归属；材料或背景不得单独冒充任务。
4. 时间保留 rawText、类型、标准值或 null、时区、精度和任务归属；否定语境中的时间不是当前截止。
5. 条件分别标 true、false、unknown 或 not_applicable；false/unknown 不从语义分母删除。
6. 完成标准区分“完成动作”和“取得原文明示结果”。
7. 取消、替代和修订分别记录 from 新端点、target 旧端点、effective 及方向；多个对象不能合成一个端点。
8. 无任务的资讯来源仍需完整标出 information 和 forbidden inference，不能用空标签掩盖漏项。
9. 无法判定的字段写入 ambiguity，不猜测。`coverage=partial` 的来源不能进入完整来源通过率。

## 4. 复核者 B 与裁决

- B 在不知道模型输出的情况下独立检查最小义务数量、拆合、别名、字段、证据和禁止推断。
- 每个分歧必须写入 `ADJUDICATION_TEMPLATE.csv`，保留 A 值、B 值、理由、最终值、裁决者和时间。
- 未解决分歧、多个合理最大匹配、自由文本完成标准不明确、修订方向不唯一或参照遗漏时，状态保持 `UNRESOLVED`，阻断整包冻结。
- 冻结后不得静默覆盖 Expected。合法订正只能追加 corrections log、提高 referenceVersion，并使所有旧请求身份失效。

## 5. 签名与交接

- A、B 分别声明未接触候选输出和历史答案、没有模型辅助、标注在 Candidate12 冻结之后完成。
- 签名使用稳定匿名 ID、ISO 8601 时间和提交包 SHA；无需在仓库记录真实姓名。
- 完成包必须一次性交给验证器。验证器只检查结构、哈希、匿名化和重合，不决定语义正确性。
- 候选实现者只有在所有参照冻结后才能接收机器生成的请求身份；不得在此之前查看正文或 Expected。
