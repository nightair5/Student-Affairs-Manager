## 已实现什么，为什么有用

1. **先分清要不要做，再判断做什么。** 新评分版本 v7 接受“未进入名单，所以没有当前任务”；也接受保留不可执行的条件事实。unknown 仍须核对，不能当 false 丢掉。动作/对象、时间、材料、完成标准、依赖、独立事件和取消替代分别判定。
2. **把匹配和错误分开。** 错时间的任务可以是任务存在 TP，同时有时间错误；多余任务为 FP，不一律叫 Forbidden。证据有必要、允许、无关、矛盾之分。空匹配、空任务和部分参照不再触发旧评分异常或自动满分。旧 v6 和 6.0.1-diagnostic 未改。
3. **错误关系只阻断相关项。** 缺失旧端点、拿 scope ID 当任务 ID、旧要求仍可执行都会标错；程序不编造端点。浏览器中错误海报项被阻断，无关预约项能单独确认；D11 S10 的真实坏引用不能冒充正确无任务。
4. **保留用户能完成的闭环。** 来源、原回答、程序适配、人工编辑分开保存。事件修改、无任务确认、任务修改、拒绝、部分确认、原子保存失败后手动恢复、独立读回和刷新都有实际浏览器证据。
5. **修改量有真实依据。** low-edit-v2 用保存前后字段差异、editId、commitId、readback 连起来。拒绝多余任务算结构性纠正；阅读不算编辑。缺提交、缺读回、刷新中断等输出缺失，不补 0。历史 measurement 3.2 未改。

新 Candidate16 为 `real-input-source-semantics-16` / `recognition-prompt-candidate16-1.0.0`，明确最小动作对象、条件真假/未知和真实取消替代端点；默认候选未变。匿名正反例证明这些接口规则和保存保护可执行，**不能证明模型遵守新提示词的概率已经提高**。
