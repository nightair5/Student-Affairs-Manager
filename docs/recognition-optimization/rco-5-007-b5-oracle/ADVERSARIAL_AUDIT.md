# RCO-5-007-B5 新鲜对抗审查

## 裁定

`FAIL / P2 GENERALIZATION NOT ESTABLISHED / PAID MODEL BLOCKED / DO_NOT_LAUNCH`

B5 在冻结提交 `578d2a3` 后只运行一次。16 个案例全部可评分，Task Precision/Recall/F1、`requiresAction` 和任务边界均为 100%，Complete Task Case 为 93.75%，Forbidden 为 0；但预先单列的“旧要求完整失效表达”只有 50%，因此不能用总体高分掩盖修订主线失败。

## 唯一决定性失败

- `rco-task-b5-08` 原文是“先前规定须发送宿舍分配表，现声明该规定不再有效。新的要求是核对房间编号。”
- 新要求被正确形成并默认勾选。
- 旧“发送宿舍分配表”没有被标为 `past + cancelled + superseded`，而被保留为 `future + pending + active`；它虽未默认勾选，但用户仍需删除一条陈旧建议。
- 因此修订案例整例正确率 50%、旧要求完整失效表达 50%、陈旧任务 1、被默认勾选的陈旧任务 0。

## 第一性原理根因

P2 仍把“是否为旧要求”和“是否已撤销”分别交给两张封闭词表，再靠两类词同时出现推断修订。它没有表示“哪一条新陈述撤销了哪一条旧指令”的关系，也没有解析“该规定”指向前一条规定。于是把“旧安排/取消”换成同义但新颖的“先前规定/该规定不再有效”，含义没变，系统却失去修订关系。

这不是缺少一个同义词那么简单。继续把“先前、此前、原先、先前版本……”逐个加入词表，只会沿着无限语言表面追赶，无法保证新表达。

## 根治方向（本轮未实施）

下一机制应新增本机“修订关系解析器”，输出明确关系而不是布尔关键词：

1. 把每条指令、状态声明和替代要求先分成独立命题。
2. 用相邻范围、指称类型和对象一致性解析“该规定/前述安排/上一版要求”指向的旧命题。
3. 本机构造 `cancels/supersedes/amends` 边，并把证据范围绑定到边；模型不得直接决定 `selected`。
4. 旧任务保留审计记录但不进入当前待办；新要求独立按当前义务和安全策略判断。
5. 用已见 B5 只做故障回归，再冻结全新 B6 做首次零调用门。B6 过门后，才值得付费检验模型选择 scope/action/object 的上游质量。

本轮未修改 P2、B5 Expected/dataset/freeze、既有 checkpoint/cache 或稳定路径，未启动 RCO-6，也未部署。
