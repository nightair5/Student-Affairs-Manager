# RCO-5-010 完整命题与三值行动性根治计划

## 1. 目标

本阶段只做 0 次模型调用的隔离实现与测试，解决 B9 暴露的两个根问题：

1. 计分器必须按数据内容比较，不能因 JSON 对象的键排列不同误报失败。
2. 系统必须能区分“确定现在有任务”“确定现在没有任务”“现有证据还不能确定”，不能把默认勾选、关键词或模型犹豫直接当成结论。

本阶段不修改 B9 或更早的 Expected、freeze、dataset、checkpoint、cache 和运行结果；不接稳定路径，不调用模型/网络/Secret，不启动 RCO-6，不部署。

## 2. 第一性原理

产品真正要回答的不是“句子里有没有动作词”，而是：

> 原文是否对当前用户形成了一个仍然有效、尚未完成、必须执行的动作命题？

因此识别链必须把以下概念分开：

- **动作词**：例如“核对”。它只说明文字中出现了一个动作表面词。
- **完整命题**：谁在什么语气、什么时间、什么状态下，对什么对象做什么。
- **行动性**：这个完整命题是否构成当前用户现在仍需处理的义务。
- **默认勾选**：即使存在义务，是否安全到可以预先勾选。外发、付款等真实义务也可以不默认勾选。

`selected=false` 绝不等于 `requiresAction=false`；出现“核对”也绝不自动等于存在核对任务。

## 3. 新的最小职责链

1. 继续使用冻结的本机 scope 和候选 ID，只定位原文动作 occurrence 与对象闭集。
2. 新增“完整命题裁决层”，读取候选所在完整 scope，而不是只看动作前后的几个字。
3. 裁决层只做可证明的本机降级：当完整句的主干是在陈述信息未知、说明缺失、界面名称、引用、历史或已完成状态时，将其中动作标为非任务；有歧义则保持未知，不猜。
4. 冻结 composer 处理裁决后的候选账本；单条非任务不得影响兄弟候选。
5. 新增独立三值行动性决策器，依据任务命题、候选覆盖和未决关系形成 `true / false / null`，不读取 `selected`。
6. 新评分工具使用递归结构比较：对象键顺序无意义，数组顺序仍有意义，值变化必须被发现。

旧 B9 链和结果保持原样；RCO-5-010 只新增版本和只读回放产物。

## 4. 完整命题判别规则

首轮只处理可泛化且能用正反例证明的结构，不建立无限关键词表。

### 4.1 可确定为“信息状态陈述”

候选动作处于同一完整句中，句子的最终主断言是“尚未说明、未予说明、仍不明确、尚不清楚、仍待明确、有待说明”等信息状态，并且没有明确祈使/义务标记直接支配该动作时，该动作只是被谈论的内容，不形成任务。

例如：

- “核对蓝色门签是否属于该流程尚未说明。”→ 主断言是“尚未说明”，不是要求用户核对。
- “核对结果仍不明确。”→ 主断言是结果状态，不是新的核对指令。

### 4.2 必须保留为指令或未知的反例

- “请核对蓝色门签是否属于该流程。”→ “请”直接支配动作，是指令。
- “必须核对结果，说明尚未补充。”→ 前半句已有明确义务，不得被后半句的信息状态吞掉。
- “核对工作尚未完成。”→ 可能表示任务仍待完成，不能按“尚未”二字判成非任务。
- 无法唯一确定主断言支配关系时保持未知。

测试必须使用成对变形：仅改变句末主断言、义务标记、标点或语序，确认分类随命题结构变化，而不是随单个关键词变化。

## 5. 三值 `requiresAction` 契约

- `true`：至少一条有原文证据的命题能证明它是面向当前用户、当前有效、肯定、必需、未完成的义务。是否默认勾选不影响该结论。
- `false`：没有任何当前义务，并且所有可能承载义务的候选均已被证据证明为非任务、历史、已完成、已取消、可选或明确属于第三方；不存在仍可能改变结论的未决候选/关系。
- `null`：既不能证明存在当前义务，也不能证明所有潜在义务均已排除；任何可能改变结论的未决命题都必须使结果保持未知。

优先级固定为：有当前义务则 `true`；否则有相关未决可能则 `null`；只有完成排除证明才是 `false`。

决策器必须同时给出机器可测的理由码和计数，不允许返回没有依据的布尔值。

## 6. 标签权威分层

后续 B10 每个关键结论必须分别记录：

- `semanticTruth`：不看当前实现输出，由无上下文复核者按原文语义标注。
- `implementationExpectation`：当前隔离组件应如何处理，用于工程回归。
- `reviewStatus`：一致、分歧或待裁决。
- `evidenceScope`：支持结论的完整原文范围。

实现边界标签不得混入语义正确率。B9-12 只保留为已知边界冲突，不允许被 RCO-5-010 改写或用作“语义通过”的证据。

## 7. 零调用验证

### 7.1 组件与对抗测试

- 结构比较：对象换序仍相等；嵌套值变化失败；数组换序失败；缺键/多键失败。
- 完整命题：信息状态陈述、直接指令、未完成任务、引用/界面文本、条件与历史修订成对测试。
- 三值行动性：当前安全任务、当前外发任务、只有历史任务、只有已完成任务、只有可选任务、模型未决候选、表外动作、未决修订、兄弟候选隔离。
- 独立性：篡改 `selected` 不改变 `requiresAction`；篡改行动性结果必须被本机验证器发现。

### 7.2 已见 B9 只读诊断回放

- 不执行 B9 的一次性 runner，不改其 checkpoint/result/report/freeze。
- 从冻结 B9 输入另起 RCO-5-010 诊断 runner；明确分类为 `SEEN_B9_DIAGNOSTIC_REPLAY`。
- 计数映射应被新比较器判为一致。
- B9-07 只有在完整命题裁决给出可审计的非任务证明、且其余潜在义务均已排除时才可得到 `false`；否则必须保持 `null`，不能为追分硬改。
- B9-12 必须在报告中继续标记为 `NOT_SEMANTICALLY_SCOREABLE`。

## 8. 晋级、停止与下一批

RCO-5-010 组件只有同时满足以下条件才可进入 B10 数据准备：

- 所有定向、属性变形和新鲜对抗测试通过。
- 已见 B9 的计分器假失败消失，且不改变原始 B9 结果。
- `requiresAction` 不依赖 `selected`，三值决策具备可验证理由。
- 不该勾选却勾选、兄弟候选连坐、来源/对象篡改均为 0。
- 全量 lint/test/build/security/audit 与相关冻结检查通过。
- 独立审查未发现通过修改标签、读取 Expected 或弱化失败关闭来追分。

任一项失败即停在 RCO-5-010 修复，不创建 B10。

通过后也只允许创建全新 B10：先形成语义真值与实现期望双层标签，完成至少两路无上下文独立复核、分歧清单、冻结、提交和推送，再执行唯一零调用本机门。B10 通过后才可另行申请付费模型调用；模型次数、金额上限和失败停止条件仍需单独明确授权。

## 9. 证据边界

RCO-5-010 与 B9 回放只能证明本机规则对这些测试的可解释性和安全性，不能证明 DeepSeek、OCR、图片/文件、真实材料、真人修改时间、浏览器兼容或商业上线效果。商业主线仍需依次通过全新模型盲测、RCO-6 事实级融合、真实去标识材料、真人时间、隐私安全、浏览器矩阵和 Commercial Preview。
