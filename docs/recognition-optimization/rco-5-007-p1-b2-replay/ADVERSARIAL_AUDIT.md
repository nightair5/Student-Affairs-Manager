# RCO-5-007-P1 对抗审计

## 裁定

`TECHNICAL_PASS_SEEN_B2 / ELIGIBLE_FOR_NEW_B3_ZERO_CALL_GATE_ONLY / PAID MODEL BLOCKED / RCO-6 BLOCKED / DO_NOT_LAUNCH`

P1 在已见 B2 的完美锚点回放中达到 16/16 完整案例正确，修复了上一轮暴露的本机策略上限。该结论只说明已知故障被修复，不是模型正确率、未见泛化、真实材料或商业上线证据。

## 修复是否落在主线上

是。P1 没有更换模型，也没有放宽“外部操作不默认勾选”的安全规则，而是把产品决策拆成四个独立问题：

1. 原文中是否存在当前有效、明确必做的动作。
2. 动作与对象应形成几个不同任务。
3. 每个动作会产生本机、外传、外部交互或实体世界效果。
4. 哪些建议可以安全地默认勾选。

`requiresAction` 现在由第一层直接计算，不再从第四层的 `selected` 反推。因此“需要上传，但不能替用户默认执行”可以同时表达为 `requiresAction=true`、`selected=false`。

## 对抗测试中发现并修复的问题

### 1. 互相证明的校验漏洞

首轮定向测试发现：如果同时篡改任务状态和顶层 `requiresAction`，仅检查两者是否一致会漏报。最终校验器改为重新从绑定的原文 scope 计算语义、效果、是否需要行动和默认选择，再与输出逐项比较。

### 2. 无边界关键词误判

首轮 B2 P1 回放达到 15/16，唯一失败是把“联系电话”中的“联系”当成外部动作，导致本机核对任务未默认勾选。最终分类改为：动作表面词和受控 action type 优先；对象只有以动作性词语结尾时才作为隐含操作。于是“联系电话”“联系人清单”保持普通对象，而“在线报名”“材料邮寄”仍被阻断为外部效果。

### 3. 主体词出现在对象中

“请核对同学名单”中的“同学”不是执行主体。最终只在动作之前的主语/义务前缀判断群体主体，避免把对象内容误当 actor；“其余同学须递交”仍能识别为群体义务。

### 4. 否定事实误触发条件

条件只在绑定的后续 scope 明确、肯定地复述条件事实时激活。“当前确实持续闪红”可激活，“目前没有获得资格”不会激活。缺少明确触发证据时保持 hypothetical/uncertain，失败关闭。

## 仍然存在的边界

- B2 已参与故障定位，100% 不能外推到新通知。
- 条件触发采用保守的绑定 scope 与近似逐字事实匹配；复杂常识推理、隐含条件和远距离转述会失败关闭。
- P1 只能处理模型已经提供的 scope/action/object 锚点；模型漏掉动作时，本机层不会凭空恢复。
- actor 与效果仍是受控确定性分类，不是完整中文语义理解。新的表达必须由 B3 暴露，不能在 B2 上继续追分后宣称泛化。
- 没有模型调用、真实材料、真人修改时间、浏览器验收或部署证据。
