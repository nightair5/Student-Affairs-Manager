# MAINLINE-03-I1 真实 Edge 验收协议

执行条件：新独立审查无阻断且一次适用完整工程门通过之后才启动。本协议是待执行，不是验收结果。
只用已安装Edge的新本机标签；不读旧用户/API标签、密钥/剪贴板、旧I1库或实际工作区。
启动node scripts/serve-mainline-03-i1.mjs，记录新随机origin/run/库名；只新建空v8库，第二标签不得new=1，禁止换端口或清库救失败。

## 主操作与读回

1. 实际首页粘贴旧multi正文（不预置草稿/正式任务）→生成工程建议。模型次数0；Source receipt→适配result来源不同层保存。
2. 关闭/恢复草稿，面板两项一次批量确认；实际读库0→2任务，并用原42字段口径在canonical/实际文件核对。
3. 录入旧no-date，部分/逐项确认；任务中心能找到，日历无日期独立列表，不造时间或提醒；真实jobs函数0。
4. 另一份同旧no-date用于编辑操作：逐键标题输入、明确保存；逐键补日期2026-09-18、保存。禁止fill代替逐字，不把仅显示称保存。
5. 保存前设置下一笔事务故障：实际逐键输入后保存失败，全库不变、缓冲保留、确认不能暗用未保存值；恢复后正常保存。
6. 在已保存编辑后设置确认故障：确认失败零正式新增，成功编辑历史保留；刷新读回一致。
7. 同库第二标签打开同份旧版本草稿；另一标签成功保存新编辑后，旧标签确认应STALE、零写入；刷新核对最新版本后用户主动确认。
8. 重复/过期提交不得增项覆盖；已确认的multi保留原值。至少再用一个旧multi验证部分后剩余确认、Inbox批量（或按影响范围复用记录，但不能只假设代码已通）。
9. 日期任务在日历按date_only展示，不造时刻；无日期任务与其分开。正式编辑/执行、ICS、通知继续阻断，不算验收。
10. 至少录入一个已见B8候选：显示失败/契约不可表达；来源/原raw/原模型/seen凭据保留，0新增正式任务，不回退到人工成功。
11. 点击真实App导出JSON，监听下载；若事件不可靠则定位本次真实新增下载文件，记录绝对路径/大小/SHA，解析与同库完整canonical及receipt比较。无实际文件不可PASS；不调用内部exportJson代替点击下载。
12. 刷新后从真实repository读取同库，检查原文、raw receipt、首次适配结果、用户历史与所有正式实体；全对象比较，记录副作用计数/真实jobs。

## 判定与收尾

只将上述实际操作计为浏览器验收，SSR/内存测试另表。DOM“已读回”字样不是存储证明，须检查repository实际返回的完整对象及真实导出文件。
记录每一场景的通过/未执行/阻断，不复用R1历史42/42冒充本轮。无日期、原始凭据和用户编辑须从实际文件验证。
任一错误默认选、保护变化、范围扩大、真实库访问、模型网络立即停止，留现场失败证据；不修未授权组件。
结束关闭本轮新标签，停止经PID/命令行核对的本轮server；库、下载文件、临时日志保留。不得递归删除或清库。
