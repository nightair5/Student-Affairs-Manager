# RCO-5-007-B2 零调用对抗审计

## 裁定

`FAIL / PAID_MODEL_TEST_BLOCKED_LOCAL_POLICY_CEILING / RCO-6 BLOCKED / DO_NOT_LAUNCH`

本轮先把 Expected 转成“模型已经完美找到动作和原文范围”的理想锚点，再只运行本机任务形成与安全决策层。结果仍只有 Task F1 94.3%、`requiresAction` 56.3%、完整任务案例 37.5%，主要修改率 62.5%。因此现在付费调用模型没有判别价值：即使模型完全正确，本机后半段仍会把结果处理错。

这不是模型正确率，也不是上线测试。它只回答一个更靠前的问题：当前本机规则是否有能力接住一个完美模型的输出。答案是否定的。

## 第一性原理根因

产品真正需要的是：原文中存在什么当前有效的用户动作，以及哪些动作可以安全地默认勾选。这是两个不同问题：

1. `requiresAction` 应回答“是否存在当前有效的必做动作”。
2. `selected` 应回答“这个动作能否在不替用户执行外部操作的前提下，安全地默认勾选为建议”。

当前策略却用“是否存在已默认勾选任务”反推 `requiresAction`。于是提交、上传、联系、外发等动作虽然被正确识别，但因为安全策略不默认勾选，整个材料又被错误说成“无需行动”。这是 56.3% 的主要来源，不是模型能力问题。

其余失败也来自任务形成规则的抽象不足：

- 复合动作按动词组合合并，没有先判断动作对象和目标是否相同，导致“核对宿舍名单”和“保存门禁故障说明”被错误并成一个任务。
- 条件句只识别“若”，没有把后文已经发生的触发事实与条件绑定，所以已触发动作仍被当作假设。
- 对象清洗使用过宽的“的”字截断，把完整词“联系电话”破坏为“电话”。
- 可选、否定和例外组依赖少量表面词，漏掉“可通过”“不需要”“其余同学”等结构。
- 安全默认仍近似依赖有限动词表，像本机完成“预算表”这样的低风险动作会因动词未登记而漏选。

继续添加零散同义词只能短暂补洞：开放语言总会出现下一种表达。应把主线改成“当前义务判定 → 动作边界与对象保真 → 效果/风险分类 → 默认勾选”，每一层只做一个职责，并在不确定时失败关闭。

## 逐类证据

| 失败类型 | 案例 | 直接后果 |
|---|---|---|
| `requiresAction` 与 `selected` 错误耦合 | B2-06、08、10、12、13、15 | 明明有必做动作，却输出无需行动 |
| 复合动作边界错误 | B2-01 | 两个不同对象的任务被合并，漏一项 |
| 条件触发未闭环 | B2-03 | 条件已成立，动作仍保持假设态 |
| 对象表面词被破坏 | B2-11 | “联系电话”被截成“电话”，精确任务不匹配 |
| 模态/否定/组别归属不足 | B2-10、15 | 主体、可选性或否定状态错误 |
| 安全动作分类过度依赖动词 | B2-16 | 低风险本机任务未默认勾选 |

## 对评分器的对抗检查

首次未提交的冻结候选把“共享证据范围内出现外部动作词”误算成“已选任务包含禁止动作”。这会把 B2-02 的本机整理任务误报为 Forbidden。冻结前已将规则改为只检查被选任务自己的动作和对象，并增加定向测试；数据和 Expected 字节未改。

最终结果 Forbidden 为 0。这个修正只消除了评分假阳性，没有抬高 `requiresAction` 或完整案例，因此不改变“本机层未过门”的结论。

## 数据边界与反过拟合要求

- 本轮运行后，B2 对当前策略及后续修补已属于已见数据，只能用于定位和回归，不能再作为未见泛化证明。
- 修补时不得修改 B2 Expected、dataset 或 freeze；修补通过后必须另建 B3 未见匿名集，再决定是否值得付费调用模型。

## 下一步门禁

下一轮只应做 0 次模型调用的本机策略修补：

1. 让 `requiresAction` 由“当前有效且必须执行的命题”独立计算，与 `selected` 完全解耦。
2. 复合动作只有在对象、目标和证据关系一致时才允许合并。
3. 建立条件与触发事实、否定、例外组和修订状态的确定性组合规则。
4. 保留模型给出的原文动作/对象表面词；只对明确句法模式做受控清洗。
5. 默认勾选依据动作效果、明确证据和风险等级，不再仅靠动词是否命中白名单。

先用已见 B2 做故障回归并要求理想锚点门槛全部通过；随后冻结全新 B3。只有 B3 理想锚点也通过，才值得另行授权相同模型、固定调用数和人民币上限的付费配对实验。
