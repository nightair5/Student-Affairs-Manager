## 用户现在怎样完成一条通知

唯一推荐入口：**http://127.0.0.1:6718/?automation=1**，仅本机服务运行时可用。隔离库为 `rco-mainline-01-02-i1-real-input-d21-review-session-p29`，仍使用 Workspace v8。页面标明工程回放、录制出处、构建及数据库；实时模型和真人派发机械关闭。`p29` 等是工程库身份，不是真人。

1. 选择匿名通知和手动/辅助条件，开始工程试次；看到试次状态已开始后，在新事务入口打开对应通知。
2. 同页查看原文、任务、材料、条件、时间及独立事件。需要时展开对应字段，核对原文依据。模糊或未公布时刻仍为空值；个人计划不覆盖原文截止。
3. 修改后，先看到“检查点已保存”；正式事实仍未创建。关闭、刷新、重开可恢复已持久化输入。其他标签留下的输入必须明确接管，接管事件后不需再随便改字解锁。
4. 保存草稿纠正，核对并选入本次确认；可拒绝多余事项、只保存无关联的正确项。任务与独立事件在同一正式事务确认；纯信息明确确认无任务，不产生空项目。
5. 成功提交后独立读回，再在收件箱重新打开。正式事务失败只能手动重试；已经提交而读回失败时，恢复按钮只重新读回，不再次提交。

普通无纠正单任务的必要路径是打开通知、查看摘要/依据、核对选入、正式确认、完成。含材料时另需明确材料必需性与当前准备情况；纠正时另需保存对应草稿。真实关联冲突需重载并重新核对，不能省掉这一安全步骤。没有同口径旧路径实测，步骤差和省时百分比均为 **未测**。

## 本轮实际修复

| 问题 | 实际修复与证据 |
|---|---|
| 检查点失败容易被误认为已保存 | 分开故障入口；页面明确输入仅在本页、刷新可能丢失；原输入保留，手动重试可落盘。H 的页面证据与事务测试分别保存 |
| 正式提交成功但读回失败可能重写 | 数据、commit 身份和待核实记录原子写入。待核实期间机械拒绝新正式写入；刷新后只读恢复原 commit，重复恢复不增加事实 |
| 旧清理/旧选择删除较新输入 | 清理、接管、裁决与保存按字段版本、实际输入及作者检查；浏览器实测旧事件清理被 `D20_FIELD_STALE` 拒绝，较新输入刷新仍在；旧裁决不能覆盖已作出的新决定 |
| 一项未保存编辑阻挡全部通知 | 未确认标题及选择按事项隔离；无关联正确项可以保存。依赖/修订端点进入真实读集，关联变化必须重新核对 |
| 事件恢复、父子编辑器状态残留 | 恢复无需改字；回调引用不反复装载输入。子编辑器保存后刷新父级会话元数据，保留父级输入，清除已经解决的旧冲突提示 |
| 无任务事件仍提示“草稿尚未确认” | 只在真实 `review_info` 正式事件提交标记存在时显示正式事件状态，不能凭点击或普通草稿保存称成功 |
| 恢复输入、材料核对漏记成本或重复计纠正 | 页面活动脉冲沿用原 editId；材料准备观察关联真实 `review_material` 操作，计操作成本而不伪造模型事实纠正。实际提交字段、commit、读回分别可查 |

## 事实与测量结果

精确截止/材料场景最终保存 1 个任务、1 份材料、1 个时间节点及录制回答中原有的关联事件；PDF、文件名、截止及来源依据都可独立读回。录制回答里“门户收件成功”仍作为原有事件保留，本轮没有替模型重写或称它为新识别改善。

混合场景独立读回 **Task 1 / Project 0 / Event 2 / TimePoint 4**；人工修改后的事件名称、地点保留。`周三晚` 和 `结束时间另行通知（尚未公布）` 均为 `normalizedValue=null`、vague、需确认，保留原文与依据。

无任务维护通知新增 **Task 0 / Project 0 / Event 1 / TimePoint 1**；手动纯信息通知不增加任务/项目。依赖场景保存两项待办，第二项引用第一项且保持 todo/等待前置；坏修订只保存无关联正确任务，错误关联项继续阻断。拒绝多余任务单列结构纠正，失败、部分完成、退出不从工程试次中删除。

阅读场景实际记录约 **25.8 秒墙钟 / 25.8 秒阅读 / 主动编辑 0**，另记真实等待；这是自动化工程回放，不是人的主动修改时间。事件名称、地点与一个时间表达的修改形成 2 个实际输入 episode、3 个语义字段，并可查 editId→检查点版本→草稿操作→commitId→readback；刷新导致时间不连续时整体主动时间仍为 null，原因保留，不能填 0。材料观察的真实编辑成本与“0 个模型语义纠正”并存，不能混为一项指标。
