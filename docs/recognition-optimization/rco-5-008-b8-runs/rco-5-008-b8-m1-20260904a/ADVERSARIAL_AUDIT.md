## 第一性原理判断

产品真正需要的不是“模型写出漂亮任务”，而是：每个原文行动候选都被看见、身份被正确分类、危险状态不会默认勾选、错误能够局部隔离。本轮证明对象抽取和安全默认已经较稳，但模型自由生成 directive 仍同时产生两种结构性错误：漏掉背景外观的历史行动，以及把修订状态当成行动。继续增加“请、禁止、取消”等提示词只会追逐词面，不能根治开放表达。

下一机制应把职责再缩小：本机先枚举每个 scope 内受控动作头并产生不可变 candidate ID；模型只给候选标注 `current / historical / optional / third_party / non_task` 并选择对象 scope，不能自由写 action，也不能自由创建 directive。无受控动作头的修订状态由本机关系层处理。单个模型候选不合格时只隔离该候选；只有来源绑定或覆盖账目失真才拒绝整例。历史候选即便不确定也应保留为未选审计项，避免修订关系失去旧侧。

## 对抗性否证

- 不能用 Task Precision 100% 宣布成功：这是以 Recall 75% 和两例整例拒绝换来的。
- 不能用 unsafe/Forbidden 为 0 宣布可上线：安全失败关闭有效，但用户仍会漏任务、漏历史、丢修订关系。
- 不能用 B7 已见回归满分覆盖 B8：B7 证明已知接口修复，B8 首次盲测证明模型自由 directive 仍是新瓶颈。
- 不能把代理成本当实扣金额，也不能把匿名合成 Development 当真实图片、文件或真人修改时间证据。
- 本轮失败后不得修改 B8 Expected、数据或冻结组件再重跑追分。
