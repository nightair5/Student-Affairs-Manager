# B2 错误分类与候选裁决

错误计数沿用发送前冻结的一对一结构匹配和字段规则。Task TP/FP/FN表示最小义务身份匹配；Major 是漏项、额外任务、字段错误和必需修订裁决错误的可审计项数；Severe 包括 Schema/引用失败或 D06 关键修订端点失败；Forbidden 包括额外义务与教学例越界复制。解析失败不会自动记作 Forbidden。

## 逐来源观察

- D01：四臂均 2/2 任务正确，完整来源通过。
- D02：四臂都把“取得批准”的完成标准处理错误；V10 另有时间字段错误。
- D03：四臂都额外生成“提交纸质海报”和“准备硬纸筒”，每臂 2 个 Forbidden FP。
- D04：四臂都额外生成“制作录音清单”；V01 另把材料关系挂错。
- D05：V01 的任务身份最好（3 TP、0 FP、0 FN），但仍有材料字段错误。V00/V10 多造“确认教室已开放”；V11 漏失“布置会场”的合法身份并出现多项条件/语义错误。
- D06：四臂都把两个已作废旧端点合并为一个“统一提交嘉宾名单和场地图”，违反“无合法任务合并”规则。冻结动作/对象与 active/pending 对 superseded/cancelled 规则裁决为 2 TP、1 FP、2 FN；新到旧的两条独立修订端点无法成立，因此每臂 Severe=1。

## 选择规则应用

四臂 24/24 均通过冻结 Schema 和引用有效性，且教学例越界复制为 0。V00 仍有 1 个 Severe、5 个 Forbidden、2 个最小义务 FN，并发生 D06 关键修订端点回归，直接触发：

`REJECT_CANDIDATE11`

因此不进入“增强臂是否比 V00 至少多 1 个完整来源”的选择步骤。即使单看描述性分数，V01 只减少 1 个 FP、完整来源仍为 1/6，且保留 D06 Severe，不满足净收益门槛。

本结论只拒绝 candidate11 当前冻结候选进入下一轮；它不比较真实用户转化，也不能推断某个组件在其他数据上无效。
