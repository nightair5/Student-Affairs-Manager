版本：`candidate11-b1-ablation-design-1.0.0`。状态：`B1_PREPARED_FOR_REVIEW`；模型结果 `NOT_RUN`。

## 因素和可识别结论

四臂共同使用 candidate03 加公共完成标准修正，固定 `deepseek-flash`、temperature 0、reasoning none、8192输出上限、同一JSON Schema、source、scopes、referenceTime、timezone和客户端适配器。

| 变体 | 元指令 M | 教学包 E | 调用数 | 回答的问题 |

| V00 | 0 | 0 | 6 | 公共修正底座参照 |

M主效应用 `V10−V00` 与 `V11−V01` 描述；E主效应用 `V01−V00` 与 `V11−V10` 描述；交互观察M是否在E存在时抑制示例复制并保留E的语义收益。四臂共享公共完成标准修正，因此本设计不能估计该修正相对candidate03的效应，也不能把历史candidate03结果当同期对照。

## 来源、已见程度和教学重合

六份来源均为本轮新编、作者已见的 `SEEN_DEVELOPMENT`，参照是模型辅助的单作者工程标签，独立人工复核待办。D01/D02与新增完成标准教学例结构相近；D03/D04/D06故意复用教学例词面形成反复制探针；D05把true、false、unknown放在同一来源，防止一律unknown取巧。具体来源、重合级别和用途见 `SOURCES.json`，不得转称Holdout或真人材料。

## 预定顺序与平衡

同一来源四臂连续执行，减少跨时间漂移。24个身份按下列顺序冻结：

| 调用号 | 来源 | 顺序 |
|---:|---|---|
| 1–4 | D01 | V00 → V10 → V01 → V11 |
| 5–8 | D02 | V00 → V10 → V11 → V01 |
| 9–12 | D03 | V10 → V01 → V00 → V11 |
| 13–16 | D04 | V01 → V11 → V10 → V00 |
| 17–20 | D05 | V11 → V00 → V01 → V10 |
| 21–24 | D06 | V11 → V01 → V10 → V00 |

每臂在四个位置分别出现1或2次；M和E的开关在每个位置各出现3次；12种有向相邻臂组合各出现1或2次。六个来源无法让四臂在四个位置完全等频，这一限制不隐藏。

## 失败、续跑和停止

身份、84份保护文件、授权、账本前缀/尾哈希或跨进程锁不符时，在请求前 `HARD_STOP`。transport、结算或上游是否接收不确定时立即停止整批，不自动重试；未经新授权不得重发同一单元。确定响应中的JSON、Schema、引用或语义失败进入分母，可继续固定顺序，但对应臂不能通过有效性门槛。

预算不足、达到24次、出现未裁决身份或价格漂移时停止。断点只允许从首个明确“未发送”的冻结单元继续；已结算、确定失败或状态不确定的单元不再派发。任何部分结果都不得选择候选。

## 预注册选择规则

1. 24个计划单元均须有确定结局；未解决transport、账本或结算状态使整批 `INVALID_RUN`。
2. 臂级资格要求6/6 Schema和引用有效，Severe/Forbidden=0，教学例越界复制=0。
3. false和unknown条件义务、已取消历史端点均属于完整语义分母；删除它们计FN。
4. 相对V00，增强臂不得新增任务FN，也不得在时间、材料、条件、修订或完成标准上新增Major错误。
5. 只有完整来源正确数至少比V00多1、Major不增加且任务召回不下降，才可称M或E有Development净收益。
6. 多个增强臂达标时依次按完整来源正确数更多、Major更少、Task micro F1更高、提示字节更短、固定顺序V00/V10/V01/V11排序。
7. 无增强臂优于V00时结论为 `NO_ADDITIVE_COMPONENT_SELECTED`。V00若过安全门，只能作为后续与candidate03同期验证的对象。
8. V00若出现Severe/Forbidden、完成/结果关键回归或漏掉任一最小义务，结论为 `REJECT_CANDIDATE11`，不强选其他臂。

## 设计缺口

本批不能分离旧8例和新增2例的作用，不能估计temperature=0下的生成方差，也未覆盖长通知、OCR噪声、纯资讯、真实学生措辞和多格式入口。来源与参照由同一工程作者设计，三个高重合反复制探针尤其不能当泛化证据。即使24个单元全部通过，真人编辑负担、正确保存率和商业效果仍为 `NOT_OBSERVABLE`。
