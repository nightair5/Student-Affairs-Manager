# Candidate11 B1 结构化评分参照细则

版本：`candidate11-b1-reference-rules-1.0.0`。角色：已见 Development 工程筛选。它不是独立 Holdout、人工真值、真实用户试用或商业转化验证。

## 两条彼此独立的状态轴

`coverage=complete` 只表示本批冻结契约要求的任务身份、语义、条件、完成标准、依赖、材料、时间、修订、资讯和禁止推断均已填写。`coverage=partial` 只能输出已知字段检查；完整案例、完整准确率和晋级均不可用。历史 Expected 保持原样，新增参照不得回写旧文件或旧分数。

本批六份参照均是模型辅助的单工程作者标签，同系统模型只做方法审查，`independentHumanReview=PENDING`。所以“完整工程参照”不等于“独立人工真值”。

## 最小义务与合法拆合

最小义务必须同时具备明示动作、明确对象和可独立判断的完成状态。存在不同动作、对象、条件、时间、材料归属、完成标准或修订状态时必须拆开。只有这些字段全部相同、合并后仍能逐项计分时才允许任务层合并；本批没有允许合并的任务。界面可以把同源义务放在一组，但不能减少评分分母。

- D01：2个当前义务，核对名单与条件未知的发布公示。
- D02：1个当前义务，明示取得审批通过。
- D03：1个当前义务，上传PDF电子海报；否定句用于禁止多造任务。
- D04：2个当前义务，校对与备份明确并行、无依赖。
- D05：3个当前义务，条件依次为 unknown、false、true。
- D06：2个当前义务；另保留2个已作废历史端点用于修订关系，共4个语义任务实体。旧端点不能成为当前待办或当前截止。

## 匹配和字段

任务身份采用动作别名、对象别名、执行归属和逐字依据的一对一最大匹配。别名在发送前冻结，看到输出后不得扩充。标题、描述或关键词共现不能替代身份；预测ID、数组顺序和字段顺序不得影响结论。

每个匹配任务逐项核验：执行人、言语行为、极性、状态、有效性、模态、条件值、当前可执行性、完成标准、依赖、材料、时间和出处。材料还核验required、格式、命名、数量、渠道、就绪事实与任务归属；时间核验逐字表达、类型、标准值、时区、精度和关联；修订核验类型、from、target、effective与方向。

完成某次核对只表示核对动作完成，不能扩大为核对无误或通过；原文明示“取得批准”时，批准本身就是合法结果目标。`unknown` 只在参照为unknown时正确，把true、false、明确时间或明确材料改成unknown同样计错。

## 歧义裁决

出现下列任一情形即为 `ADJUDICATION_REQUIRED`：别名外的合理等价；多个最大匹配产生不同字段结论；自由文本完成标准无法确定；修订端点不唯一；参照遗漏；自动评分器不能消解预测局部ID。未裁决单元保留在分母，并阻断候选选择，不能自动迁就输出。

D06 的两条修订必须分别是“新嘉宾名单提交 → 旧嘉宾名单提交”和“新场地图提交 → 旧场地图提交”。现有 scorer 2.0.0 可以检查任务、时间、材料及两条 effective，但不能仅凭自由ID自动证明端点方向，因此这一项必须在结果出现后按冻结动作对象规则裁决；在裁决完成前不得选候选。

## 失败与分母

确定收到的 JSON、Schema、引用或语义失败保留为该计划单元失败，不重试、不移出分母。transport、结算或上游是否接收不确定会使整批停止，待对账前不得继续。部分运行不得选择赢家。

只报告逐来源配对、完整来源数、Major/Severe/Forbidden、Task micro P/R/F1、时间/材料/条件/修订分项及描述性的M、E、M×E。六份 Development 没有统计把握，不报告显著性、泛化率或真实转化率。
