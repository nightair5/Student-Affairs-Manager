## 1. 分层口径与输入

本轮SCOPE只检验文档/证据/保护；以下是下一I1待授权验收，不是本轮已运行结果。
输入固定：src/experiments/mainline01/fixtures.ts原8类通知/响应；src/domain/v2/confirmationV2.test.ts中已登记的材料/事件/冲突关系变形；B8-01/07/09既有sourceText与parsed。
B8文件路径见SCOPE/CHECKS；只投影输入/原始响应，不把Expected、score或dataset整体传给运行模块。
新测试可对这些已见文本做显式人工字段映射和内存对象变形，不新建数据集、不叫未见或独立金标准。类型和关系测试不是新增真实语义材料。
人工新结构标签都标human_engineering；旧B8为seen_model_unverified；不改变历史预测/评分，不靠新Expected改旧FAIL。
旧linked-event工程夹具location为null，T06只验证此空值/未提供状态与事件关系保真，不冒称非空地点的语义识别或真实材料覆盖已经验证。
“旧2.0保持不变”“新语义包保真”“实际App尚未接入”必须分别出表。

## 2. 先登记失败再实施的最小正反检查

| 组 | 已见输入/变形 | 必须通过的正向结果 | 必须拒绝/保留的反向结果 |
|---|---|---|---|
| T01 完整普通任务 | multi/no-date，旧42字段 | 原对象可表达，旧V2真实内存confirm→load仍42/42；无日期0关联时间/0提醒 | 不能从显示deadline/材料名还原canonical |
| T02 条件三值 | 旧condition-true/false/unknown完整通知 | 新包独立保留条件、事实依据、true/false/unknown；true为正向核对候选 | unknown不是false/无任务；false不默认选；不能靠旧抛错过新结构门 |
| T03 当前状态 | B8-07原文、旧information/no-date及人工标签 | 当前核对与已完成整理分开；纯信息无虚构任务 | 原B8忽略scope保留；不“订正”旧fn；未复核旧模型不自动选 |
| T04 修订 | 旧revision及B8-09来源 | 旧要求取消、新要求生效独立保留；cancels可无替代；新要求正向核对 | 不把“停止执行”变成当前执行任务，不凭空建新要求，不覆盖正式旧任务 |
| T05 材料/时间 | 旧multi材料独立字段、material-only time | 原文/AST归一化/时区/精度和任务材料归属逐项不丢 | 空引用not_extracted不能当未说明；模糊/冲突/多个deadline不当无日期 |
| T06 事件/共享 | 已登记linked-event/shared-time工程变形 | 新包事件、地点、时间和任务关系完整，问题归属准确 | 旧V2仍阻断相关事件；不删event/time关系取通过，不宣称事件已保存 |
| T07 有效兄弟 | 旧multi在一项绑定坏引用/冲突/事件 | 未受影响且本身完整的普通兄弟，走原V2单项确认；待核对原项在原对象保留 | 悬空引用使整个旧2.0 validator失败时整个旧capture不放行；不得改validator救分。新包局部诊断成功≠旧capture部分存储成功 |
| T08 出处与身份 | 源ID/版本/hash错，重复quote，不一致raw/parsed | R3-CLOSE来源一致性不退化；对象顺序可忽略、数组顺序不可 | 根身份失败整份拒绝；局部证据失败准确隔离；无模糊搜索猜位置 |
| T09 权限/选择 | selected注入、stableID/位置/自由证据越权字段 | 本机生成内部标识及决策；人工明确当前无风险正例必须有非零核对建议 | 模型selected一律拒绝；全拒绝/全未知不能过门；没有人工复核的旧模型结构合法仍不是语义通过 |
| T10 变形/边界 | 数组对象顺序、稀疏数组、跨来源、循环、共享关系冲突 | 语义与实体对应关系稳定；真正相关的候选受阻，独立兄弟不连坐 | 多重关系不能取第一项静默丢失；删字段/任意注入不能放行 |

先建立失败断言/能力差异账本，再实现新语义格式，不修改旧夹具或原测试。每次失败保存attempt与主因；同根因最多两轮。
新语义包保真必须覆盖条件true/false/unknown、已完成/取消/当前、cancels/supersedes、事件关系、材料/时间多重关联。人工标签示例不是自然语言自动推理正确率。

## 3. 指标与过线条件

| 指标 | 分母/定义 | 下一I1工程门 |
|---|---|---|
| 新包事实与关系保真 | 人工工程输入明确提供的每个字段/关系；组合前后逐项和值/引用/来源比较 | 100%；missing_upstream不能补造或从原差异账本抹掉 |
| 旧42字段保真 | 原multi两任务×21，经过原V2内存确认读回 | 42/42；旧40/42/17和历史FAIL不动 |
| 行动性/条件状态一致 | 逐项true/false/unknown和not_applicable分列 | 人工状态表100%；unknown误转false=0 |
| 错误默认选择 | policy输出中不应默认选却为选的项，独立绝对数 | 0；只是本机策略测试，不是浏览器或模型误勾率 |
| 漏项/误项 | 输入明确工程任务/事实与输出核对包的逐项匹配；拒绝/未知单列 | 对可表达人工输入均0；旧B8未给字段保留missing而非补事实 |
| 覆盖与拒绝 | 所有输入/任务均进入账本，含未选/未知/结构失败 | 100%列账；条件真/有效新要求与独立普通兄弟必须有正例，不能全拒绝 |
| 原V2确认保存 | 仅等价完整旧2.0可确认子集；确认前后及load全对象比较 | 不该写/重复新增/覆盖/丢失0；新语义确认保存仍NOT_RUN |
| Evidence | 每个确定字段/关系的来源版本与合法scope/span | 100%结构绑定；语义蕴含另计，不冒称独立验证已证明事实为真 |
| Complete Case | 每一完整已见工程通知，全部字段/关系和本轮承诺结果正确 | 新结构正向案例全部通过；旧V2不支持项标NOT_SUPPORTED而非产品PASS |
| Major/Forbidden | 重大对象/时间/状态/归属变动，越权/自动正式写入/隐藏外发 | 新组合相对工程输入均0；原B8质量不重评 |

首次建议质量仅为人工工程上限；模型准确率、真人主动编辑时间、真实正确确认率、单位成功成本均本轮未测量。0模型调用/0模型费用不代表开发成本为0。
不得把NOT_SUPPORTED案例排除后发布“整个产品100%成功”。列示本轮全部输入的端到端支持数/未支持数，不能以局部条件分数替代整份完成率。
不为新包预先编造N条事实的分母：先在新报告登记由已见人工输入产生的逐项工程账本及断言，缺口项同样保留；正式模型指标/阈值不变。

## 4. 实施检查节奏与正式保存边界

1. 核对SCOPE交付提交/远端、CHECKS逐字保护与白名单；不从历史轮次重审。
2. 零调用失败复现、新结构定向及属性变形；只用内存，不启动浏览器或服务。
3. 新无上下文独立审查（≤800字）检查：Expected泄漏、默认选择、false/unknown、字段/归属丢失、全部拒绝与误报产品完成。
4. 无阻断后适用lint/type/全量功能/契约/build/security/依赖审计；使用R3已明确的历史快照与当前兼容性分层方式。旧R2工作区环境3/1单列；禁止改旧门/依赖或让其无声消失。若新工程门不能在白名单内编排，停止申请，不擅改旧checker。
5. 保护、差异、报告人工检查，明确8个实现/测试/脚本及新报告暂存清单，独立提交推送核对远端。
6. 成功后停止。下一授权必须是根据I1实际表达缺口接真实App/确认/持久化，不自动付费或新建数据。

I1不写Schema、Source/Draft/Task.legacyData，不能以那里存了任意JSON宣称有正式语义契约；若要正式保存新语义，须另批准全图校验、读取/修改/事务/刷新/导出各环的一致性，以及旧版本兼容/迁移。
