## 1. 唯一主线与所在位置

目标：让用户把文字、图片、文件中的通知，完整、正确、少修改地确认成可追溯任务。
成功链是“完整读取 → 语义正确 → 事实关联完整 → 可核对建议 → 用户确认 → 可靠保存”。
安全策略、测试和模型调用是手段；不能靠大量弃答、不勾选、手工补齐或缩小分母制造进步。

当前代码基线60332e1：RCO-0…4已有技术/组件证据；010-E1为本机安全机制验证。
RCO-G5的整份关键事实和模型净收益尚未证明，RCO-6未启动；不要从RCO-0重做，也不能跳过G5。
B8是旧模型合成Development，B9历史FAIL不变；010没有新的模型泛化成绩。
本次只交付文档，下一建议工作包是RCO-5-MAINLINE-01，状态WAIT_AUTHORIZATION。

后续顺序：

1. RCO-5-MAINLINE-01：零调用端到端工程上限验证。
2. RCO-5-MAINLINE-02：按实际缺口修正事实表达/职责，零调用候选验证。
3. RCO-5-MAINLINE-03：新Development模型配对，验证G5完整性与安全净收益。
4. RCO-6：文字/图片/图片+文字消融，冻结采用或不采用视觉的决定。
5. RCO-7：两批独立真实材料、真人效用及正式浏览器验收。
6. RCO-8：单独批准Commercial Preview后收集运行证据，Production再审批。

上述新工作包属于既有RCO-5，不新建一套晋级门；编号不构成调用许可。

## 2. 先解决什么，不解决什么

按“受影响频率、漏事/错事损失、用户补救时间、证据可信度、改动成本”排序，不凭代码是否容易修改决定优先级。
频率不明时写未知，先用已授权Development诊断；不编造用户统计。

| 优先问题 | 所属层 | 当前证据与先做的事 |
|---|---|---|
| 时间、材料等在候选→建议途中丢失 | 构造/适配 | 新候选baseTask存在空引用，先用正确人工响应验证能否完整保留 |
| 候选表找不到正确动作/对象 | 表达能力 | 模型只能选择已列候选；先测正确答案可表达性，再决定新契约 |
| 只读到长通知开头 | 提取/调用 | 本机chunks已有，调用仍截24,000字且提示；验证范围/跨块关系，预算另批 |
| 条件、执行人、旧新要求混淆 | 语义 | 完整语境判断与本地来源验证分开，未知保留；不再无限补关键词 |
| 正确建议仍难确认 | 交互/存储 | 复用实际确认和v8事务，检查无日期、部分确认、重复提交和恢复 |
| 不知道用户省了多久 | 测量 | 设计主动编辑/等待/总时间及首次/最终结果区分，不立刻采集真人数据 |

暂不扩展：支付、账号同步、微信、自动外发、项目记忆、复杂自主Agent、全面页面改版、模型大规模扫参。
这些范围以后可以提案，但不能代替完整通知闭环。

## 3. 分层输入输出与诊断责任

| 层 | 输入与输出 | 失败分类 | 负责验证 |
|---|---|---|---|
| 本机提取 | 文件/文字 → 带页段范围的文字与partial标记 | encoding、page_missing、reading_order、ocr、truncation | 程序夹具；真实格式后续授权 |
| 语义理解 | 当前原文/范围与引用目录 → 最小完整事实 | action/object、actor、modality、condition、currentness、revision、association | 独立语义标签；模型只提议 |
| 本机构造 | 有证据事实 → 时间AST/材料/事件/任务有效引用 | unexpressible、missing_field、dangling_ref、wrong_projection | 共享组件和一致性测试 |
| 安全建议 | 完整候选 → 选中/未选/待核对建议 | unsafe_default、over_abstention、sibling_collateral | 独立误勾指标及覆盖率 |
| 用户确认 | 首次建议 → 编辑/拒绝/部分确认/最终处置 | hidden_error、forced_fake_date、abandon、duplicate | 工程交互与后续真人观察 |
| 正式保存 | 用户选择 → DomainCommitPlan与v8事务 | data_loss、overwrite、invalid_commit | 隔离数据库读回、故障注入 |

本机编号和原文位置可信，不等于模型语义正确。分类器不能更改原文动作；执行人不能猜；条件与事实句、旧要求与新要求要各自有出处。
原文无日期与日期不确定分开。unknown不静默变false；旧布尔客户端不能表达时必须显式报告兼容缺口。
失败只影响有问题的候选；根来源/版本/指纹不可信时整份拒绝。
语义复核器并非默认必需：只有独立对照证明净收益、费用另批后才考虑加入。

## 4. 当前下一包：RCO-5-MAINLINE-01

### 4.1 唯一问题

给定人工已写正确且有原文依据的响应，现有产品组件能否完整展示建议、允许正确确认，并在隔离存储中读回一致结果？
本包只验证工程上限，不测模型识别率，也不生成“新未见数据通过”的结论。

### 4.2 授权与保护

- 尚未授权。申请范围：仅零调用本机验证，可新增隔离适配、工程夹具、测试入口、度量定义及报告。
- 不修改冻结组件/契约/Expected/dataset/checkpoint/cache，不运行旧一次性runner，不创建B10，不改RC.4、稳定路由或部署。
- 不读取Secret；禁止外部识别模型请求、verifier、Repair和retry。
- 原有测试组件可只读调用。确认写入仅使用新建的独立测试数据库/内存repository，绝不连接用户正式工作区。
- 若必须修改受保护契约或产品公共入口才能实现，记录差距和最小变更提案，在该边界停止；不能复制一套玩具实现绕过真实组件。

### 4.3 实施顺序

1. 核验Git、当前用户授权、保护清单和依赖；追加阶段开始快照。
2. 追踪实际App→capture→recognize→draft→DomainCommitPlan→repository；列出未接入的研究组件。
3. 建立纯工程参考响应：正确、有缺字段、错误关联、有歧义、无任务；工程输入与评分断言隔离，明确不是模型输出。
4. 先走既有完整RecognitionResult合法路径验证确认上限，再检查新候选→该路径的最小适配及无法表达字段。
5. 验证原文时间、材料、条件、事件、修订到建议字段和确认实体的全链一致性。不能以统一空数组/默认值让契约通过。
6. 验证客户端真实组件的编辑/拒绝/部分确认/无日期/重开恢复；不能仅跑composer就称端到端完成。
7. 检查最终repository，不以toast或提交按钮点击作为写入成功证据。
8. 形成缺口优先级和后续计时事件设计；不采集真人资料。
9. 定向验证→独立审查→适用工程门→保护核验→文档/日志→单独提交推送后停止。

### 4.4 最小主线场景

| 场景族 | 必须证明 |
|---|---|
| 单任务/多任务及共同材料 | 不过拆、不少拆、材料跟对任务 |
| 无日期/date-only/明确时刻/模糊日期 | 不造日期；精度/时区保留；有歧义可确认 |
| 纯信息/问句/命令/可选/禁止 | 提示不同，requiresAction与selected分开 |
| 条件真/假/未知、跨句事实 | 条件不凭孤立字判断，未知不冒充无需行动 |
| 已完成/历史作废/新要求生效 | 不重新布置旧事，不静默覆盖已确认任务 |
| 长来源尾部要求/跨块说明 | 部分覆盖明确；尾部未读不算全份成功 |
| 单项错误/根来源篡改 | 单项隔离不连坐；根完整性失败拒绝整份 |
| 失败/部分确认/刷新/重复提交 | 来源保留、正式写入只由确认触发、无重复或丢失 |

每族有正常与故障/成对变化，不按案例编号或某个固定中文句子写特殊规则。至少一个真实客户端组件与隔离存储联动场景。
本轮没有真实OCR时，入口模拟必须写EXTRACTION_FIXTURE；不能称浏览器/OCR商业验收。

### 4.5 产物与通过线

- 隔离验证入口和最小适配（具体路径在获批后记录）；工程夹具独立标记，不混入历史或未来Holdout。
- 一张“输入→提取→首次建议→用户处置→存储”的字段保真表，覆盖动作/对象/时间/材料/证据/状态。
- 对正确可表达响应：端到端字段保真100%，错误默认勾选0，未确认正式写入0，重复/覆盖/丢失0。
- 对错误/不可表达响应：明确失败或待核对，不能假装完整；误勾和遗漏分母均保留。
- 报告清楚区分实际产品组件、适配/模拟范围及NOT_RUN；有缺口则本包PARTIAL/NO_PROMOTION，不宣称全闭环通过。
- 保护哈希不变，审查无阻断，适用工程门通过；主线后续是否可继续以当前授权为准。
- 结束后只申请MAINLINE-02，不自动改模型职责、创建盲测、启动G6或部署。

## 8. 统一结果记录与真人测量

每轮只保留一张主线结果表：版本、输入范围、计划/完成、Task/Time/Material/Evidence、
Complete/Major/Forbidden/误勾/未知、失败类型、延迟、观测成本、用户指标状态。
缺真值写NO_INDEPENDENT_GROUND_TRUTH；缺真人写NOT_RUN；不将工程期望作为语义真值。

程序记录：匿名试次与版本、提取/识别/可交互/确认/读回阶段事件、修改类型和终态。
独立标注者：完整语义及关系、重大修改与危险错误；标注冲突先裁决，不能按实现改真值。
观察者：用户在哪里找不到依据/需要补录/放弃。
用户问卷：主观负担、重复使用意向、付费意愿；不冒充正确率或收入。
所有真人/真实数据动作另批，默认不上传编辑内容或用于训练。

预先定义active（实际核对/编辑）、wall（全程）、wait（程序等待）和idle/后台规则。
首次建议与编辑后终态分开；部分确认、拒绝/无任务、失败、退出保留。
正式对照按商业契约平衡顺序与难度，避免同一人重复同一材料的熟悉效应；
实际网络体验与冻结输出回放时间代理分开，不相加后伪称实测。

## 9. 迭代、上下文与验证成本

- 每轮首屏：目标、授权、当前工作包、唯一根因、允许改动、保护对象、验收/停止线。
- 启动只读AGENTS、PRD相关节、CURRENT_CONTEXT、日志最新追加段、当前工作包及直接源码；商业执行前才完整读取适用商业契约，不每轮读全部历史。
- 先rg/字段摘要再行段；原始输出、base64、巨型checkpoint不进入对话。
- CURRENT_CONTEXT目标约80行，上限200行且12 KB；放当前事实/授权/证据路径/下一步，不复制整份路线。
- 工具输出尽量控制30行摘要，长日志写入获准位置。恢复只核对Git与证据，不重复已完成实验。
- 一个主根因最多两轮修补；每轮问“能否减少漏项/误项或用户修改”，不能只报告新增测试数。
- 定向工程验证→一次新鲜独立审查→必要修补复核→一次完整工程门；文档阶段做链接/一致性/读者测试/diff/安全扫描，不为文档改动重跑付费或一次性实验。
- 代码阶段仍执行lint/test/build及适用安全、依赖、冻结和部署前检查。全量日志只保留结果摘要；红灯不能宣称完成。
- 独立审查按最小相关包无上下文交接，同系列模型审查不等于独立人工真值；审查结果控制800字以内，主要查授权、真值泄漏、误勾、来源/对象和主线缺口。

## 10. 停止与恢复

沿用AGENTS的三级停机，不重新定义：
HARD_STOP用于错误分支/越权/隐私/保护污染；REJECT_CANDIDATE用于新增回归；
NO_PROMOTION用于证据不足或未达到质量。已知旧失败是待诊断对象，不是假装新事故。
保护文件变化、Expected进入决策链或测试被弱化立即停止写入和模型请求，保留现场。
一阶段验证后单独提交推送，准确记录失败；交付完成不自动授权下一阶段。
恢复时核对原授权、分支HEAD、保护与数据是否已见；历史FAIL不改名、不覆盖。
