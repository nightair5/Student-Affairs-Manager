## 根因

candidate08 的文字指令允许同一来源片段建立多个角色，并要求实体只引用“与实体同类”的角色；JSON Schema 只能约束 `evidenceRoleIds` 是字符串数组，不能在生成时直接限制其所指角色类别。模型因此经常把支持同一句事实的动作、材料、时间角色一并挂到任务或材料上。

转换器按照冻结契约拒绝这些组合是正确的 fail-closed 行为；若放宽转换器、丢弃多余角色或自动改引用，会隐藏模型没有遵守事实职责的问题，并违背“不补造、不删错来制造通过”的边界。因此本轮没有在看见结果后修改候选、Schema、转换器或评分口径。

下一次唯一优先方向不是继续加警告，而是先把输出契约压缩为 JSON Schema 能直接表达的单一拥有者字段，例如每个实体只允许一个明确的 owner role，并把其他来源依据放入不参与类型判定的独立 evidence refs。是否再调用模型，应在该零调用契约能承接已有正确响应后另行决定；本轮不创建 candidate09。
