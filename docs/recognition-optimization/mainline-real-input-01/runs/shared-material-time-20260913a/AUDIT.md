# 共享材料时间归属修复：零调用交付审计

## 用户得到的变化

此前两个任务共用一份材料时，本机会沿着“任务A → 共享材料 → 任务B的截止时间”继续遍历，把两个截止时间都挂到每个任务上。页面因此报 `MULTIPLE_DEADLINES`，即使模型已经把两个时间分别归属正确，用户也无法继续确认。

现在时间归属只按现有的明确任务关系传播：任务A只取得A的时间，任务B只取得B的时间；共享材料仍保留全部真实任务关联。仅属于材料本身的提交时间仍会保存，但不会伪装成任务截止。真正由同一任务拥有的多个冲突截止仍然阻止确认。

## 实现边界

- `semanticComposer` 在限定职责内隔离“共享材料”和“任务私有时间”，冲突判断只统计任务实际拥有的截止时间。
- `semanticState`、`factCorrections` 的核对视图、日期编辑支持和正式实体投影采用同一归属规则，避免页面正确但提交仍使用旧传播结果。
- U11-09、V02-09 加入6632匿名历史回放；candidate09仍为 `NOT_ADOPT`，页面明确这只是历史回答与本机修复验证。
- 完整库导出和独立仓储工程证据改为“先准备、再显示真实下载链接”，不再在异步读取结束后程序化 `click()`，降低浏览器丢失用户激活导致下载无文件的问题。
- 模型入口仍关闭；没有新增候选、调用、数据或依赖。
