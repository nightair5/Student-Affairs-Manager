# candidate09 派发前业务口径

本轮20份全部是已见材料开发回归，原12份与后8份分别统计；同一通知两臂相同文字、时刻和时区，每臂独立一次。旧评分器、参考事实和首次回答不改。

## 三类结果分开

- 实质错误：改变用户要做什么、何时做、需要什么、什么条件下做，或取消/替代对象。漏任务、多任务、漏材料、规格错误、归属错误、错误日期/条件/关系分别计数，并写具体纠正。
- 等价表达：名称近义但对象相同、同一日期不同原文粒度、材料合并或拆分后仍完整保留规格与归属、多个等价来源scope引用。单列，不直接算实质错误。合并导致用户看不到某个必需对象或错误共享则仍为实质错误。
- 结构阻碍：协议拒绝、坏引用、覆盖冲突、无法进入核对。即使模型语义可理解，也单列为额外操作/不可用，不伪装为语义正确或正常完成。

无需实质纠正：完整通知中没有实质错误；另报其中能直接进入核对的数量。不把用户核对材料必需性和明确选择unverified算作修正模型事实；但记录实际操作成本。缺少信息或调用失败不算成功，分母不删除。

任务/材料的实质误漏按独立应做动作或必需交付对象计数。某字段同时错误与漏掉相同对象的正确形式，只计该字段错误，不再重复计为独立漏项。保留严格评分的FP/FN原数以供对照。

## 本轮采用与产品样例

采用需：实质错误和必要纠正减少，任务漏项、时间、条件、修订与结构可用性无明显退化。明显取舍则不自动替换candidate03。先完成20对分析，再作结论，不追分追加调用。

产品选例优先原12第1或第11 / 后8第1的多任务与材料，以及原12第7或第12的新旧关系；检查同来源是否已确认，避免重复两臂。新路线失败时使用已有可承接的candidate03或Q01/Q07历史回答，明确候选身份，照常完成正确任务确认保存。不得假装前置完成。

原始模型事实、确定性转换、用户修改和最终保存分别保留。代理操作不是实际真人编辑时间或总体转化率。模型比较不使用浏览器准备状态猜测。
