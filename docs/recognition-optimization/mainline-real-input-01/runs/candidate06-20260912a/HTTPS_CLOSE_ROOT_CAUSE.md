## 材料准备状态：另一个真实限制，不混成模型错

当前模型wire材料只含required/规格/归属等，不含准备状态；不能把required=true计成模型声称已经准备好。`factCorrections.ts:6-14` 的用户MaterialDecision需要选择MaterialStatus；当前只有missing/preparing/ready/submitted/verified/not_required，没有“尚未核实”。`semanticState.ts:300`在材料核对模式要求先有用户decision，再保存required/status，并标记user_observation。

因此原文没有准备状态并非解析丢失；用户尚不知道自己的准备状态时，是核对表达能力限制。不能为完成验收强选“确实缺少”，也不能用not_required伪装未知。此前内存测试显式选missing只代表工程测试用户选择，不代表原文真值。本轮仅登记，不修改冻结MaterialStatus或扩展确认职责。
