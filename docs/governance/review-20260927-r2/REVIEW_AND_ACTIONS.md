# 全局复查：把项目推进重新对准正确与省事

日期：2026-09-27。审查起点：`930b88198690b35d246bbdfd4370258cd2906c1c`，分支 `codex/e2-candidate11-blind-eval`。性质：Codex 工程自审与公开资源研究，不是独立人工质量鉴定。

## 1. 结论与审查范围

当前最影响推进的并不是缺少新模型，而是三个环节没有对齐：产品希望整份通知被正确处置；评分却漏查关键事实；测量又可能把阅读当修改、漏记批量保存前的纠正。继续堆 Prompt、生成新批次或增加审计轮数，暂时无法可信地回答“更正确了吗、更省事了吗”。

治理改版已经解决一部分旧规则叠加问题，但 README、PR 模板、旧总计划和本机专属工具仍存在入口不一致。本轮修正这些活动文件，保留旧实验记录和拒绝结论，给下一轮工程提供可复现问题与验收清单。

审查覆盖：对起点的 2,815 个 Git 跟踪文件建立清单；筛查 479 份 Markdown/文本的旧阶段授权、全新 Development 要求、旧 PRD 章节、个人绝对路径和在线状态声明。命中 98 文件、169 行，仅为人工复核线索，不是 169 个已确认缺陷。重点逐项复核了现行规则、README/RUNBOOK、PR/CI、最新交接与计划、D7 审计、保护工具、评分与测量相关代码。**未逐行审计全部源码或每份历史 raw，也未重新验收线上服务。** 原始范围统计见 [REPOSITORY_SCAN.json](REPOSITORY_SCAN.json)。

## 3. 必须修正的产品和评测根因

| 优先级 | 证据/根因 | 大白话后果 | 下一版应改什么 |
|---|---|---|---|
| P0 | D7 独立事件时间只查 rawText/scope | 写对原句但把活动时间变成 1900 年，仍可能被评为整份正确 | 新版 scorer 逐项查类型、归一化值、时区、精度、全天、待确认与对象归属 |
| P0 | Prompt 对无任务 informationScopeIds 的允许集合与 scorer 不同 | 模型遵守提示词也可能被扣分，比较不公平 | 建立同一语义投影，证明合法输出可达到完整分 |
| P0 | 材料包装/完成标准、待公布/截止含混 | 把格式要求当办结证明，把将来通知日期当提交日期 | 新版 provisional 裁决与可接受集合；不能测的明确标不完整 |
| P0 | measurement 2.4 从 suggestion_interactive 开始累计 active | 用户只是看了 10 秒，也会被写成改了 10 秒 | 分开阅读、真实编辑、等待、隐藏、空闲；编辑区间有开始/结束与预注册规则 |
| P0 | 实质修改要求 edit、commit、readback 使用同一个 operationId | 页面先改字段、再统一保存，可能把修改记录成 0 | 显式 edit→commit 批次映射；缺映射标不可判定，不默认零；首次到最终差异作交叉核验 |
| P1 | 计时汇总只用已判定行，缺失/未决覆盖需更清楚 | 数据缺失可能被忽略，省时表象来自挑样本 | 每种终止状态报 n、缺失原因和负担；失败前编辑也保留 |
| P1 | 浏览器关键路径仍缺当轮真实证据 | 单测通过不说明实际按钮、保存与刷新能用 | 独立入口使用真实组件与 repository，完成浏览器回放；不可用时保留 NOT_RUN |
| P1 | 历史裸测试与旧 hash 失败仍存在 | 全量测试/CI 仍不能直接称绿 | 单列维护包查入口环境约定；不削弱旧断言、不改旧锁伪造通过 |

前三项来自 [D7 架构决定](../../recognition-optimization/candidate14/d7-blocked/ARCHITECTURE_DECISION.md)，本轮不重写其记录。测量问题则本轮实际复现：

| 匿名工程输入 | measurement 2.4 实际输出 | 为什么不符合 PRD |
|---|---|---|
| 没有任何编辑，阅读 10 秒后确认、提交和读回 | activeEditMs=10000，实质修改=0 | 阅读不应自动算主动修改 |
| 首次错误，发生时间纠正，使用另一个 ID 批量保存并读回 | substantiveEditCount=0，lowModificationCorrectDisposition=true | 缺 edit→save 对应时不应把已观察的语义纠正当无纠正 |
| 没有编辑，浏览 10ms 后超时 | activeEditMs=10 | 应保留超时与阅读负担，但不冒称编辑时间 |

完整输入、模块哈希及输出见 [MEASUREMENT_COUNTEREXAMPLES.json](MEASUREMENT_COUNTEREXAMPLES.json)。复现命令：`node scripts/audit-candidate14-measurement-readonly.mjs`。只构造 ENGINEERING_REPLAY 与内存读取；无真实人员、业务模型调用或数据库写入。输入中的“语义正确”是人为构造的工程判定，不是独立人工标签。

上述证明模块对这些可构造事件的处理存在口径缺口，不证明当前真实用户已经发生了同样错误；还需下一版验证 UI 实际事件如何映射。现有被冻结 measurement/Prompt/scorer 保持原样，另建新版修复。不能说这轮已经提升了识别率或修好了产品指标。

## 4. 不必继续加严的地方，以及仍应保留的规则

| 容易妨碍推进的做法 | 现在的合适做法 |
|---|---|
| 所有历史规则取最严并集 | 当前 PRD/AGENTS 按范围生效；旧冻结批次按旧合同复现 |
| 每改一次工程代码就重造全新 12 份数据 | 已见 Development 可迭代；正式配对派发前冻结一次；独立 Holdout 保持未见 |
| 没有独立人工就停止一切 | 继续工程、模板与 provisional 开发；只暂缓独立准确率与真人结论 |
| 普通文档必须浏览器验收、Preview 部署 | 文档检查链接和一致性；产品交互才验收真实页面；发布才执行发布门 |
| 每个小补丁再开窗口/分支、更新多份完整日志 | 当前目标继续同一工作区；完整边界提交推送，一份短交接链接长证据 |
| 把本机测量做成抵抗设备所有者的防攻击系统 | 满足错归属、重放、误改与可追溯即可；研究记录与远程可信证明分开 |

仍须保留：用户确认后才能正式落任务；原始来源与修改历史；条件/时间不确定性；旧记录不可篡改；付费调用次数和预算；密钥只在服务端；真实人工不被模型冒充；正式发布按已批准协议。这些规则保护结果可信，不是当前效率问题的根源。

## 5. 外部资源如何服务主线

完整 20 项资源、许可核对和本地映射见 [资源目录](RESOURCE_CATALOG.md)。本轮没有发现可以直接装上就证明本项目四指标提高的“万能库”。最接近的组合是：

1. CheckList / 属性变异测试：先检验尺子会不会漏掉关键错误。
2. LangExtract 的证据定位思路：让用户从错字段一步回到原文。
3. HAX 与任务产品的交互模式：让用户局部修改、快速恢复，减少多余操作。
4. 空白模板或 Label Studio / Doccano：组织真实独立参照；工具不代替人。
5. 现有 OCR、PaddleOCR、Docling：在确认读取错误是主要原因后，做输入专项。

优先采用方法和本项目已有库，不一次引入所有框架。具体外部事实及来源均在资源目录；以上顺序是针对本项目当前证据的判断。

## 6. 后续每一步怎样推进

| 顺序与工作包 | 具体产出 | 通过标准/停止范围 |
|---|---|---|
| W1：统一语义与评分 | 逐语义对应表；新版 reference/adapter/scorer；正例与单字段变异矩阵 | 每类完整参照有可达正确 wire，已知关键变错必失败；歧义/表达缺口不算满分 |
| W2：确认与测量闭环，可与 W1 同批 | 真实组件工程入口；纯信息、无日期、部分确认、失败恢复；新版事件模型 | 独立读回与刷新一致；阅读不计编辑；批量纠正不漏计；缺失不填零 |
| W3：候选与 Development 准备 | 最小必要新候选、promptVersion、共享评分；新批次完整材料与零调用身份 | 冻结前调试，派发前固定；R4/R5 身份不复活；未满足契约就不准备可调用包 |
| W4：获新授权后配对 | 已核价、预算与请求绑定、一次发送、真实 raw/usage、首次结果 | 执行预注册门槛；失败保留；结果只说明开发筛选，不替换默认候选 |
| W5：独立质量与真人效用 | 冻结候选后独立 A/B 参照；另行授权的真实试次 | 无答案污染；全部合法试次入分母；四指标、缺失/失败及不确定性分层 |
| W6：按证据决定首发 | 支持范围、运行/隐私/成本、回滚、正式验收与发布申请 | 只有达到已批准发布契约且获授权才替换或部署 |
| 输入专项：按错误分布插入 | Tesseract 基线 vs 一种新解析器；同来源同后续语义链路 | 关键字/页段覆盖与整份正确同时改善；成本、延迟和人工校对负担可接受 |

每个工作包都对应四指标中的具体风险，不以“又冻了一批”“又做了几轮审计”作为产品进步。W1—W3 可在一个已授权的大任务里连续推进；到外部调用、真人或发布才按对应范围取得授权。完整下一步提示词已更新在 [D8](../NEXT_STAGE_EXECUTION_PROMPT.md)。
