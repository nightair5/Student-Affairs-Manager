# 学生事务管家：D15 后主线推进路线

更新：2026-09-28。以 [D15 一体化结果](../recognition-optimization/candidate16/d15-integrated/D15_RESULTS.md) 为当前证据，旧 D14/D13 和 D11 仅作各自历史快照。主线目标仍为提高首次整份建议正确率、正确处置率和低修改正确处置率，降低主动修改时间。

| 顺序 | 具体工作 | 要得到的证据与停止边界 |
|---|---|---|
| 1. 定向修 Candidate16 的实际风险 | 先固定 D15 原 raw/评分/错误清单；对 S10 不存在旧任务引用、S02 材料和时间回退、S11 superseded/currentness 做 1—3 个根因修复，另立候选版本与 promptVersion。加入匿名正反例，修复本地关系保护和 UI 冲突恢复引导。 | 离线反例、真实 Schema/adapter/scorer 往返、浏览器可编辑/局部确认/失败恢复；不在已见 D15 答案上改 Expected，也不把工程回归当模型提升。 |
| 2. 做一次新版本的公平 Development 筛选 | 新候选和 Candidate03 共用来源、Schema、adapter、评分与参数；在新输出前冻结身份、参照、风险不退步项和预算。需要新的模型/次数/硬上限授权。 | 逐来源进步、退步、未知；关键 FN、无据新增、错误时间和关系单列。若仍有无效引用或严重风险，继续定向修复，不靠总分抵消。 |
| 3. 完成真人探索前的产品准备 | 使用 D15 已验的每人独立库和两条件入口，补“先事件后任务”的清晰重载提示，冻结 3—5 人×每人4条匿名通知的来源/辅助 raw SHA、顺序和 low-edit-v2 阈值；真实负责人安排同意与裁决。 | 取得参与者和明确试用范围授权后才可运行；记录首次建议、最终处置、低修改与主动修改时间的分母、缺失和争议。工程点击不能转成人类时间。 |
| 4. 独立质量验证 | 候选冻结后准备真正未见来源，独立 A 标注/B 复核，冲突裁决与签名；另行批准独立 Holdout 调用。 | 区分 Development、独立文本质量和真人效用。没有独立人工不能宣称 Holdout 真值。 |
| 5. 发布决策 | 综合独立质量、真人处置、风险、依赖审计和回滚方案，另行申请默认替换、合并和部署。 | D15 本身不授予上线资格。 |

D15 已完成的事实：24/24 冻结请求结算；Candidate03 整份正确 2/12、Candidate16 3/12，但 C16 一份引用失败、7 个 Severe，预注册结论 `NEEDS_TARGETED_FIXES`。4 项真人指标仍 `NOT_OBSERVABLE`。账本合法追加 49 行且保护/冻结通过。全量旧 carrier/5秒超时测试与依赖审计失败作为维护项单列，不能写成全绿，也不作为无限增加审计轮次的理由。
