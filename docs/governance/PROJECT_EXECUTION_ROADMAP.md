# 学生事务管家：D20 后产品推进路线

更新：2026-09-29。[D20结果](../recognition-optimization/d20-review-session/D20_RESULTS.md)是当前事实入口。目标仍是提高首次整份建议正确率、正确处置率、低修改正确处置率，并降低实际主动修改及总处置成本。D17 原成绩 C03 1/12、C17 2/12 与 `MIXED_PROGRESS` 不改；D19 的事后诊断不是新模型效果。

| 顺序 | 用户价值与工作 | 可核验完成条件 |
|---|---|---|
| 1. 收尾 D20 核对会话 | 将材料、动作/对象、条件、依赖、修订关系和事件时间全部接入同一来源的未确认缓冲；事件/关系冲突显示用户语义，保留双标签输入；正式保存仍走单笔 DomainCommitPlan 与 CAS | 浏览器 A–L 逐项验收；特别是双任务依赖正式读回、局部阻断、保存失败恢复、纯信息 0 Task/0 Project、双匿名身份隔离、真实字段纠正到读回；未通过项明确原因 |
| 2. 测量与受限探索准备 | 把页面 editId、检查点、commitId、独立读回直接关联；manual 录入与 assisted 纠错分开；保留未闭合、失败和退出在分母 | 匿名工程报告可逐试次看四项口径、分母/缺失、中位数及来源/刺激 SHA；只有真实负责人、同意、参与者和范围授权后，才运行 3–5 人×每人4条的探索试次 |
| 3. 有假设的新识别比较 | 先裁决 D19 未决参照，再判断是 Prompt、adapter 还是评分问题；仅在模型输入/机制需变化时建新候选和冻结新 Development | 对照与样本量由错误假设决定；请求不含 Expected，模型/次数/硬费用另授权；逐来源风险和整份正确分开报告，不把总分抵消关键遗漏 |
| 4. 独立质量验证 | 冻结候选后用未见来源与真正独立人工 A/B 参照验证；保留未决和覆盖不足 | Holdout 结果、严重风险、缺失及不确定范围可审查；不能用开发集或模型自评替代 |
| 5. 受限发布与成熟化 | 前四步可用后，再决定默认候选、预览、合并和部署，完善备份、恢复、可访问性及依赖维护 | 每项另有授权和回滚；独立浏览器/真实流程、相关测试与安全通过，在线后继续观测真实完成、修改和留存 |

这些是直接前提而非一把总锁：不能因没有新模型许可暂停安全的本地交互修复；也不能因工程回放成功就宣称真人省时。短期优先级是用户能完成一份通知、不会丢编辑、不会误保存、能看到正确处置与修改成本。暂缓 OCR/多模型/知识问答扩张、支付及复杂项目自动化。历史路线见 Git/D18 存档；[下一工作入口](NEXT_STAGE_EXECUTION_PROMPT.md)只写剩余直接任务。
