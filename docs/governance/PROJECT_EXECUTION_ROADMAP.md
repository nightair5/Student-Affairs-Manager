# 学生事务管家：D14 后主线推进路线

更新：2026-09-28。按 AGENTS、PRD 与 [分层规则](PROGRESS_POLICY.md) 执行；当前事实看 [D14 一体化结果](../recognition-optimization/candidate16/d14-integrated/D14_RESULTS.md)，历史 D13 与 D11 仍单独保留。

主线是提高首次整份建议正确率、正确处置率和低修改正确处置率，并降低主动修改时间。D14 已把预算、未授权停发执行器、隔离两条件试次和实际浏览器/读回做在一个本地包里。C03/C16 新比较尚未调用，四项真人指标都缺数据；**不能把准备完成说成 Candidate16 胜出**。

| 顺序 | 接下来实际做什么 | 得到什么证据与决策 |
|---|---|---|
| 1. 完成一次冻结 Development 比较 | 用户另给本批 `deepseek-flash`、仅24次及美元硬上限的明确授权；执行前重核官方价格/路由、最终 HEAD、Manifest/请求 SHA、权威账本。只按冻结顺序最多发送一次；不确定即停发 | 24 个结局确定后用冻结 v7 同口径逐来源比 C03/C16，报告整份、任务、关键字段、严重风险、改善/退步/未知；标题/泄漏未人工覆核标 `NOT_ADJUDICATED`。已见合成 Development 只筛候选 |
| 2. 补手动混合边界，开展授权后小规模探索 | D14 已验逐字完成标准/材料和纯信息独立事件开始时间；继续补任务与独立事件并存、多事件/结束时间及每人独立库，做新库浏览器验收。取得真实负责人、3—5 参与者、同意和范围授权，再按冻结平衡顺序每人4条 | 首次建议、最终处置、低修改及主动编辑时间的真实观察和缺失报告；小样本用于定位用户费力点，不宣称统计显著性 |
| 3. 针对确凿回退修根因 | 只选 1—3 个对当前任务漏检、无据新增、时间或修订错误有实际影响的原因；新候选与规则版本化；先离线反例后按需新调用 | 改善、退步与修复成本逐例清楚，不因一个总分抵消高风险错误，也不因旧严格门阻断独立工程收益 |
| 4. 独立验证 | 候选冻结后准备未见通知，真实独立 A/B 标注/复核；另定材料和预算授权 | 只在声明支持范围内判断泛化与真人效用，不能用已见 D13/D14 或工程夹具冒充 |
| 5. 默认替换与发布 | 确定范围、质量/安全阈值、回滚及生产链，获得单独授权 | 才考虑改默认、合并、部署；D14 未进行这些动作 |

D14 的新预算保守占用 US$7.785696，建议申请 US$7.80 硬上限，见 [具体卡](../recognition-optimization/candidate16/d14-integrated/BUDGET_AUTHORIZATION_CARD.md)。价格会变化，卡本身不授予模型调用。旧 D11 拒绝不改、旧 grant 不复用。真人探索与模型比较可独立推进，但所有真人百分比必须来自真实注册试次及裁决；工程回放时间不能填充。
