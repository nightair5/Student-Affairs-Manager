# 学生事务管家：D18 后产品推进路线

更新：2026-09-29。依据 [D18审查](d18-product-direction/REVIEW_AND_DECISIONS.md)与PRD1.2。目标不变：提高首次整份正确、正确处置和低修改正确处置，降低实际修改及总处置成本。下列是工作顺序和直接前提，不是把全部阶段串成一把总锁。

| 阶段/负责人 | 要完成的用户价值 | 直接前提与实现 | 可审查交付/停止条件 |
|---|---|---|---|
| D19-A 契约与测量尺；工程执行者 | 正确事实不被模板误罚，真风险能定位 | 用D15/D17旧raw；统一交付物/依据、条件-依赖-生命周期、时间/关系单向权威；新scorer/selector双臂诊断，旧版不变 | 合理替代表达通过，错对象/时间/生效/漏事件反例失败；24分母保留；未决不满分；不产出新模型成绩 |
| D19-B 统一核对入口；工程执行者 | 一份通知在一页核对，不在Tools与产品页往返 | 复用App/正式编辑/DomainCommitPlan；ReviewSession共享缓冲；同来源任务和事件一次计划；受影响项隔离、真实冲突保留编辑 | 新隔离入口、来源/依据/修改/局部确认/无任务归档、失败手动恢复、独立读回与刷新；新构建实际浏览器证据 |
| D19-C 真实对照准备；工程执行者 | 能看见辅助是否省事 | 语义字段分组新测量版；manual/assisted分组；主动/阅读/等待/墙钟与缺失；注册/刺激/读回绑定 | 工程例给可核验输出，真人全NOT_OBSERVABLE；同页完成测量；已有空表复用 |
| 探索试用；用户指定真实负责人 | 找到普通用户真正卡住的操作 | D19保存安全、错误可见、测量可用；3—5人×4条不同匿名通知的范围授权、同意和负责人 | 逐人/来源的正确处置、时间、修改、退出/缺失；小样本探索，不宣称泛化或统计稳定；不必等模型全面胜出 |
| 新Development比较；工程执行者 | 验证明确机制的模型收益 | 契约已统一；新Prompt/adapter确有变化；旧失败回归集和新增覆盖；先冻结候选、参照与批次预算，再申请明确调用授权 | 规模由假设决定，非默认12×2；最近候选对照、C03锚点按事前选择；一次发送零重试；逐事实改善/退步/争议，不改旧结论 |
| 独立质量验证；真实A标注/B复核 | 验证冻结候选对未见通知的可靠性 | 首发范围/参照规则先定，开发者未见材料，候选冻结；模型批次另授权 | 独立质量、缺失、置信范围与风险；样本量按目标精度/严重风险设计，不把模板重复当独立样本 |
| 受限预览与成熟化；工程执行者+用户决策 | 稳定日常使用、备份恢复、明确边界 | 获批首发契约；正式主路径集成；相关全量测试/安全/依赖/浏览器/回滚；明确默认替换/合并/部署授权 | 路由与构建可确认，失败恢复、成本与数据控制可运维；上线后再验证再使用/留存/长期遗漏 |

D19-A/B/C 在同一工作包连续完成，按可审查边界提交。候选语义变更待契约确定后才创建下一个空闲编号，不把“下一步一定Candidate18”写成前置目标。仅修adapter或评分就按对应版本命名。首发假设聚焦作业/报名/材料提交/简单活动，复杂修订明确人工接管；范围在未来采样前冻结，不从旧分母删除难例。

维护作为主线支撑：现行测试编排让Vitest/Node/server/worker/functions分别执行并汇总，旧冻结复现失败单列；定位超时与carrier，重核依赖风险。每次验证只因新改动/失败/疑点扩展，不重复已通过项。暂缓更多OCR/云视觉、自动多模型复核、知识问答扩张、账号支付和复杂项目功能。

四项真人指标没有数据时保持缺失；候选文件存在、测试多、预算卡完整都不是效用证据。每个交付记录唯一入口/模式、用户动作、读回、测量与限制。没有外部授权时完成全部安全本地工程，明确缺哪项材料，不再重复“准备准备包”。
