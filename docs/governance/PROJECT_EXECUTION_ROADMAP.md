# 学生事务管家：先完成可信核对，再获取真实反馈

更新：2026-09-30。当前状态 [D21 PARTIAL](../recognition-optimization/d21-review-session/D21_RESULTS.md)：数据丢失竞态、双标签旧字段提交和人工事件更名校验已修，任务+两事件正式读回、正式事务失败/手动重试已有最终构建证据；A—L 仍有具体缺项。目标仍是首次整份建议正确、正确处置、低修改正确处置与主动修改时间；真人四项全为 NOT_OBSERVABLE。D17 原成绩 C03 1/12、C17 2/12、MIXED_PROGRESS 不改。

| 顺序 | 工作 | 进入下一步的实际条件 |
|---|---|---|
| 1. D21 余项闭环 | 正式提交失败已验；继续完成检查点与提交后读回故障注入、各编辑类别刷新恢复、不同字段双标签双方正式保存、关系与来源版本冲突、双身份全图隔离；同一匿名场景记录必要步骤 | 最终构建 A—L 每项有页面与独立 canonical 读回，相关安全/测量测试通过。旧路径未同口径测量则如实标未测 |
| 2. 获准小规模真实探索 | 复用 3—5 人×每人4条、手动/辅助各2条的已准备工具 | 明确负责人、试用范围授权、参与者真实同意与匿名来源/辅助刺激冻结；逐试次报告成功、失败、退出、缺失和中位数，不用小样本推断总体 |
| 3. 针对性识别修复，可与探索准备并行 | 从 D19 风险和探索真实失败挑 1—3 类根因，定位 Prompt/adapter/scorer/界面 | 公共代码先离线回归；仅需新模型输出时才冻结候选、参照、对照及预算，另取模型/次数/费用授权，不默认24 |
| 4. 独立质量与效用验证 | 用未见来源及真正独立人工 A/B 参照评价冻结方案 | 报覆盖、严重风险、争议与不确定性；开发集和工程回放不能顶替 |
| 5. 受限发布与运营 | 默认切换、合并、部署各自取得授权并有回滚 | 来源核对、备份/恢复、可访问性、安全与线上监测通过，再观察真实修改成本及完成率 |

保存安全与明确试用授权是探索前提；候选整个开发集胜出不是。默认路由、隔离录制入口和开发分数分别陈述。暂缓 OCR、多模型编排、支付及复杂项目自动化；当前欠缺是可操作路径的最后验收，不是再建一批模型身份。
