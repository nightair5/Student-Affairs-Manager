## 独立验证与首发

1. 明确首发支持范围：先选择可核对的文本通知和核心行动闭环；对暂不支持的复杂修订给出透明人工入口。范围在正式验证前定，失败与回退都保留分母。
2. 候选冻结后，用独立人工参照评估未见材料。实验选样、阈值、停止规则和预算提前确认；不看结果后降低要求。
3. 使用获准真人试次验证正确处置、低修改、主动编辑和阅读/总耗时。示范点击与程序时间不得混入。
4. 默认替换、Preview 与 Production 单独提请授权，并验证真实服务与回滚。不是把整条研究分支直接合并。

## 如何防止再次陷入循环

- 当前工作包只排三类根因；新增想法进待办，不随手变成新门。
- 评分问题用已保存回答定位，输入/候选改动才需要新模型证据。
- 阻碍写明影响哪一项。缺独立标签限制独立结论；评分失败限制相关分数；不阻断安全工程回放。
- 每轮最终报告分别说工程交付、开发观察、探索准备、独立证据、发布状态，避免一个拒绝状态掩盖全部进展。
- 旧 PRD/路线/结果从存档读取，不在活动文档顶部无限叠加“最新”。
