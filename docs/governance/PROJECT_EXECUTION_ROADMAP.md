| 顺序 | 用户价值与工作 | 可核验完成条件 |
|---|---|---|
| 1. D21本地产品完成包 | 先修清理竞态、事件恢复不能直接保存及错误成功提示；全部目标字段共用会话，同页冲突和正式提交；测量直接关联，减少重复操作 | 最终构建浏览器A–L、独立canonical读回、丢输入/失败/并发反例、同场景步骤对照、editId到readback直接记录；不要仅以PARTIAL再交准备包 |
| 2. 获准受限真实探索 | 复用3–5人×每人4条、手动/辅助各2条的工具，观察是否省事与具体卡点 | 负责人、同意、范围授权；固定通知和辅助录制刺激；逐例正确处置/修改量/时间、分母与缺失。小样本不宣称泛化 |

| 5. 受限发布与成熟化 | 前四步可用后，再决定默认候选、预览、合并和部署，完善备份、恢复、可访问性及依赖维护 | 每项另有授权和回滚；独立浏览器/真实流程、相关测试与安全通过，在线后继续观测真实完成、修改和留存 |

这些是直接前提而非一把总锁。没有模型许可不阻断本地工程；没有模型全场景胜出不阻断获准的小规模探索。保存安全、可恢复和可测是探索前提；独立泛化、默认替换与发布各有证据要求。不要因旧无关断言或缺真人停下可完成工程，停止须说明真实阻碍。
