## 1. 目标、适用范围与阅读顺序

- 以 [PRD](PRD.md) 定义的四项主指标为目标：首次整份建议正确率、正确处置率、低修改正确处置率、主动修改时间；F1、测试数量和审计轮数只提供辅助证据。
- 开始任务先读本文件、PRD 相关部分和 [CURRENT_CONTEXT](docs/recognition-optimization/CURRENT_CONTEXT.md)，核对实际工作区、分支、HEAD、工作区改动。然后按需要读取当前工作包和涉及的契约，不重复加载全部历史。
- 产品需求以 PRD 为准；执行流程以本文件为准；当前进度以 CURRENT_CONTEXT 指向的实际代码、提交和结果为准。旧日志是带日期的证据，不是永久的当前状态。
- 指令优先级遵循平台规则与用户当前明确要求。项目内部冲突按适用范围和生效版本解决，不能简单把所有历史条款取最严并集；安全、数据保护和该批冻结契约继续有效。
- P0/P1/E1/E2、RCO 和各 Candidate 的旧阶段禁令只约束当时工作包。它们不再禁止已获授权的新候选开发，也不要求重跑所有已完成阶段。
- 历史商业契约 0.6.0-draft 仍是未批准的全范围草案；其中样本量、九格式和商业门不套用到日常修复。正式验证或发布采用哪份契约必须预先明确，不能事后降低门槛。

## 2. 授权与自主推进

| 工作 | 在已授权任务内如何执行 |
|---|---|
| 阅读、分析、设计、文档、匿名本地夹具、代码修复、定向测试 | 连续完成，不为每个文件、补丁或旧阶段编号再次询问 |
| 阶段内实现→验证→修复→交接→提交推送 | 属于完整交付；一个任务可以覆盖多个相依工作包 |
| Development 数据和评分器修订 | 可版本化迭代；保留来源、已见程度、差异和旧结果 |
| 免费本机预览与工程回放 | 使用隔离端口和数据库；不得借此操作旧库或冒充真人试用 |
| 业务模型调用、付费 API、grant/reserve/settle | 必须已有适用于该批请求、模型、次数和费用的明确授权；过期或已耗尽许可不可沿用 |
| 真人招募/试用、真实材料采集、对外发送 | 必须已有对应范围的明确授权；不能用模型代替真实参与者 |
| 合并、部署、默认候选替换、Production、旧用户库迁移或破坏性操作 | 必须已有相应明确授权，并满足相应验收门 |
| 新依赖、Schema 变更 | 先说明必要性、影响和兼容方案；明确禁止时不做，超出当前授权范围才询问 |

文档和可复制提示词不自行创造执行授权；用户提交执行提示词后，按其中范围连续推进。已有授权无需重复确认。2026-09-28 本轮执行规则审查、零调用诊断与必要工具修复；业务模型、真人研究和发布仍需相应授权。

## 3. 交付节奏与上下文

1. 先确定用户失败、证据缺口、改动范围和可验收结果，优先修复影响整份正确和用户操作成本最大的根因。
2. 同一工作包可同时修复相依的 Prompt、adapter、scorer 和 UI。整包比较只能归因于整包；要证明单组件收益时另做受控消融。
3. 连续两轮局部修补无效时，做一次根因与接口审查，必要时改为架构修复；这不是要求停止全部已授权工作的机械计数器。
4. 每个可解释、可验证、可回退的交付边界创建 Conventional Commit，并立即推送当前功能分支；不逐个小补丁提交，也不拖到巨型不可审查提交。
5. 推送后核对本地 HEAD、upstream 和远端 SHA。失败保留本地提交并准确记录，不强推、不伪造同步成功。
6. CURRENT_CONTEXT 保持简短，只保留一个当前状态和下一工作包；旧正文按日期归档并链接。路线图、提示词和跟踪表不得继续堆叠互相冲突的“当前/下一步”。每个交付边界更新一次必要索引，不为每次命令复制多份日志。
7. 同一目标与工作区继续当前聊天。达到自然交付点、转入不同目标或上下文反复混淆时，写交接后再开新聊天；只有确需并行隔离或不同基线时才另建 worktree。同一文件避免多写者。
8. 不因历史计划提到审计员就自动增加代理。委派遵循当前用户及工具规则；一个有效的边界审查通常足够，新发现和高风险改动才追加。
9. 每轮交付单位是一个可操作的用户场景，记录“入口/运行模式 → 改善 → 证据 → 尚缺什么”。候选编号、文件数、测试数和预算卡本身不代表产品效果。受限探索与语义修复可并行，探索不以开发候选胜出为前提；真人范围授权仍必需。
10. 开发优先复用录制回答和稳定回归集。评分变化先做双臂只读诊断；候选/输入变化才需新输出。批量大小由待验证假设决定，不默认再造 12 份和 24 次调用。每批仍须明确模型、身份、次数及费用授权，不滚动复用余额或旧 grant。

## 5. 产品与数据不变量

- AI 只生成可编辑、可拒绝、可追溯的建议。正式任务必须由用户确认，不能静默创建、合并、覆盖已确认内容。
- 有行动的来源生成建议；纯信息来源可以正确归档；不确定来源提示核对。任务中心只接收用户确认的任务，不强迫所有输入产生任务。
- 任务必须是动作加明确对象；材料、格式、地点、联系方式、背景、禁止项不能单独冒充当前任务。取消和替代分别按动作、对象及端点处理。
- 所有推断标记 explicit、strong_inference 或 optional_suggestion。默认仅勾选明确、当前有效且行动条件成立的任务；保留漏项、过度未知和误勾指标。
- 条件 true/false/unknown 分开；日期缺失、模糊、冲突分别表达。不得补造默认日期或把 unknown 静默映射成 false。
- 重要字段能回到来源依据；逐字引用有效不等于语义正确。修改 Prompt 更新 promptVersion，并补充匿名正反回归例。
- 当前 Workspace v8 是唯一持久化事实源。顶层材料、时间、证据、历史与提醒不能被旧 Task/Draft 投影覆盖；兼容视图不进入正式确认提交。
- 识别前先持久化 Source、SourceVersion、RecognitionRun 与 Draft。正式确认使用 DomainCommitPlan，在单个 IndexedDB 事务内完成，失败不留下部分正式任务。
- 保留逐项编辑、拒绝、部分确认、保存失败恢复及独立读回；确认项不被后续识别覆盖，未确认草稿不创建空项目。
- Schema 迁移必须先备份、内存迁移、全图校验及 round-trip，再原子替换；无法判定的旧字段保留 legacyData。不能通过修改 PRD 顺便执行迁移。
- 无任务归档、首次输出锚点和测量记录应防止误改、重复和错归属；本机隔离存储不宣称能抵抗掌控设备的攻击者。不为尚未需要的威胁模型不断叠加防护层。

## 6. 实验与评分纪律

| 证据用途 | 可迭代性与冻结要求 | 能说明什么 |
|---|---|---|
| 工程夹具 / 已见 Development | 可复用、调试、版本化修改；模型辅助参照标 provisional | 契约可表达、代码防回归、已见开发效果 |
| 一批正式 Development 配对运行 | 首次派发前冻结输入、参照、请求、参数、评分器、门槛；作者和已见程度公开 | 固定开发集上的候选筛选；不冒充未见泛化 |
| 独立 Holdout | 候选/规则先冻结，开发者不可先看新参照；独立人工标注与复核、泄漏隔离 | 在所声明样本范围内的独立质量证据 |
| 真人效用 / 发布验证 | 预注册、授权、实际行为及真实浏览器和运行证据 | 正确处置、修改负担、服务可用性 |

- 开发集无需每修一次代码就丢弃再造。旧 R4/R5 失效身份仍禁止派发；已见文字可作为未来版本的回归/开发资料，必须改其用途声明且保留失效史，绝不能重新称为新 Holdout。
- 启动正式配对前，证明每类完整参照都有可达的正确输出，且改变关键语义的反例会失败；检查 Prompt→wire→adapter→reference→scorer→用户处置一致。
- 接受语义等价的别名、顺序及合法拆合，按预定义规范判定；原文引用、ID、时间值和对象归属等必要字段仍严格。不能逐条为候选输出定制答案。
- 完整参照与部分参照分开；不可表达、不可测和有争议的字段不能默认正确。分母、缺失数量、覆盖范围与未决语义同时报告。
- 两臂共享公共适配、评分和失败规则；在看结果后改规则只能成为新版本诊断，不能改写原运行结论。
- 传输、解析、Schema、引用、语义失败分开；全部计划单元保留。重试、repair、verifier 按该批明确授权和冻结策略，不默认增加。
- 实际 token/费用与预算上界分开。不可观测用 NOT_OBSERVABLE；授权执行器负责跨进程锁、一次发送、reserve/settle 和未知发送状态停发。不得读取或输出 Secret 明文。
- 模型或同系列代理审查是 provisional 工程审查，不能署名为独立人工真值。独立人工只在需要独立语义或真人结论的阶段成为必要条件，不阻断本地契约修复。
- 候选未过门就停止晋级和对外宣称，仍可继续已授权的诊断与新版本开发。所有历史拒绝决定保留。

### 6.1 开发进展不再只有一个 PASS/FAIL

- 每次交付分别列工程状态、开发观察、探索试用准备、独立质量证据和发布状态，不汇总成单一“全部失败”。工程回放不依赖评分通过；其依赖来源/数据库隔离、错误可见和保存安全。
- 历史“24 个确定结局、两臂全有效、零 Severe/Forbidden、FN/Major 不增加、整份净增 2”继续约束原批次；不再自动复制为所有未来工作共同门槛。新比较在派发前指定目的、主指标、风险不退步项和选择规则。
- 开发优先级看真实错误减少、可确认范围和纠正负担；保留整份严格正确率，同时报告字段、场景、未决和回退代价。不得用加权总分抵消错建禁止任务、错误改写已确认事实或漏报关键截止。
- 修评分器可复用两臂原始回答，标事后诊断；只改评测无需重新付费生成。改输入/候选后的新效果须新证据，不把录制输出冒充新版输出。
- 评分器异常是测量故障；参照争议是待裁决；未匹配任务是 FP/FN；禁止行动是语义风险。四类分开，不能用同一 Forbidden 标签代替。
- 每个严重标记必须能追到具体事实、发生层和用户后果。scope 冗余、片段边界、表示 ID、派生状态差异不得未经裁决就写成“模型捏造事实”。参照通过自己制作的正确样本，只证明可满足；还要覆盖独立的合法替代表达及关键语义反例。
- 新实验评估按用户义务和事实比较，原始输出、确定性转换、用户纠正分别报告。任务/事件遗漏、无据可执行性、时间错挂等风险独立列出，不能只盯旧 Severe 总数。裁决不明保留分母和未知，不临时调分。
- 新规则不能追溯改成旧候选 PASS。缺少独立人工只限制独立质量声明；获单独授权的小规模探索可用单人暂定裁决并公开身份、争议和缺失，不冒充独立 Holdout。
- 工作中最多优先处理三类高价值根因；将可安全并行的修复、回放、测量接入放入同一交付包。优先移除根因，不再以增加审计轮数、候选编号或新造数据作为进度。

## 7. 按影响分层验证

| 改动范围 | 必需检查 |
|---|---|
| 纯文档 | diff、链接/路径、前后规则一致性、敏感信息检查；触及保护文件时运行对应保护检查 |
| 独立校验脚本/工具，未改产品运行时 | 工具定向测试、相关 lint、只读保护和敏感信息检查；无需无关浏览器或全产品构建 |
| 产品规则、Prompt、adapter、scorer、业务组件 | 定向正反例；交付边界运行 lint、test、build；涉及隐私/服务加 security:scan |
| 用户交互、确认保存、恢复、迁移 | 上述检查加真实浏览器和持久化路径；定向覆盖错误与恢复，不能以单测冒充点击验收 |
| 发布候选 | 全量测试、lint、build、security:scan、npm audit --audit-level=high、cloudflare:check，以及对应已批准发布协议 |

- 阶段内先跑最相关检查，交付边界再跑全量；无新改动、失败或新疑点时不重复已通过检查。
- 不为低风险文案修改写镜像测试。对评分器必须测“合理答案能过”和“关键错误不过”，测试不能只复述实现。
- 新增或受改动影响的失败必须修复。既有且经证据确认无关的失败可以作为已知问题保留，并交付不依赖它的本地改动；不得宣称全量 PASS，不得削弱断言凑绿。
- REAL_INPUT_CARRIERS_MANIFEST 和 RCO-5-007/旧 package-lock 历史问题单列。若本阶段依赖其正确性，则该交付仍受阻；修复需新版本工具或独立维护工作包。
- 浏览器工具不可用标 NOT_RUN，保留原始错误；可继续无依赖的代码和文档，用户端验收状态不升级。
- 审查强度随影响提高。普通文档/局部规则可自审；评分器和实验执行器需要正反例及独立视角复核；正式独立标签、付费派发和生产发布保留各自门槛。

## 8. 停止范围与诚实交付

- 未授权外发/付费、发送是否发生不明、预算锁失效、可能写错用户库：停止该危险操作并保留现场。可继续与风险无关的只读分析。
- 错误分支、并发冲突或未知工作区改动：先核对与隔离；能安全解决的工程问题自行处理，不能擅自覆盖。
- 评分契约失败：停止使用该契约给出候选晋级结论或新付费派发；按授权修复和补测试。
- 缺独立人工：停止独立质量结论，仍可完成模板、工具和 provisional 开发。
- 最终报告区分“代码/文档已交付”“质量待验证”“发布未授权”。说明改动、有效证据、剩余风险、提交/远端状态及最有价值的下一步，不要求每次附超长提示词。

## 9. UI、技术与外部服务
