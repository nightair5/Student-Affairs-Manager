## 1. 产品目标

帮助大学生把通知、消息和文件快速处理成正确、可追溯的行动或信息记录，减少遗漏、实质修改和操作时间。用户保留决定权；自动结果始终是建议。

主线围绕四项指标，按同一来源的完整闭环评价：

| 主指标 | 用户真正得到的价值 |
|---|---|
| 首次整份建议正确率提高 | 第一次就给全、给对，不用逐项找漏项和错项 |
| 正确处置率提高 | 最终确认的任务或无任务归档符合原意，并可靠保存 |
| 低修改正确处置率提高 | 大部分通知不用增删任务、改关键时间或修正条件 |
| 主动修改时间降低 | 需要修改时，能快速定位、改对、继续处理 |

“模型响应成功”“JSON 合法”“任务 F1 提升”“按钮点击完成”均不足以代表产品成功。正确性和省时一起优化；不能用全部弃答、全部不选、强迫用户重填来获得表面安全。

## 3. 目标用户与工作范围

优先处理课程作业、报名、材料提交、会议活动和更正通知。优先做好已正确提取文字之后的语义与确认闭环，再逐步扩展复杂版式和劣质图片。

| 范围 | 现在怎样安排 |
|---|---|
| 文字、TXT、Markdown、已提取的文档正文 | 当前质量修复与确认体验主线 |
| 单/多任务、无任务、条件、修订、多时间、材料共享、依赖 | 当前必须覆盖的语义风险 |
| 本机 DOCX/PDF、OCR、分段与跨页关系 | 保留已有能力；按入口错误的实际贡献开展独立工作包 |
| 云端图片与文字融合 | 可选实验；只有独立授权及净收益证据后才能申请启用 |
| 首页、任务中心、日历、来源/文件库、项目档案 | 消费同一已确认数据，保持可用；不扩展成新的 AI 决策系统 |
| 账号、支付、微信、自动外发、跨设备云同步 | 不属于本轮识别主线 |

这是开发优先级，不是缩减旧冻结实验分母或授权更小范围上线。未来可以提出边界明确的文字首发方案，但须在收集其正式评测材料前批准独立范围和验收契约。

## 4. 用户闭环

1. **录入与读全**：粘贴或在本机读取；显示真正处理的页/段范围，乱码、超限、漏页和 OCR 不确定性可见。
2. **先保存来源**：持久化 Source、SourceVersion、RecognitionRun 和 Draft，关闭页面后可继续。
3. **生成建议**：识别动作、对象、条件、时间、材料、事件、完成标准和修订关系，附可定位来源。
4. **按结果处置**：有行动进入待确认；无当前任务可归档信息；不确定只突出待核对部分。
5. **低成本核对**：摘要卡展示关键字段、缺项和风险；点字段回到原文，直接修改、拒绝、拆合或部分确认。
6. **可靠落地**：确认后的任务通过统一事务保存并独立读回；失败保留草稿，重复提交不重复创建。
7. **后续行动**：任务进入任务中心、首页、日历与提醒；纯信息进入来源档案，不创建空项目或虚假任务。

多个时间点不等于多个任务，多个材料名也不等于多个任务。拆分依据是需要分别完成和确认的行动义务。

## 5. 识别语义契约

### 5.1 什么是一个任务

任务必须有动作和明确对象，并属于当前有效的行动要求。按独立交付物、执行动作、截止、操作方式或依赖确定合法拆合；同一义务的背景、重复表达和格式说明不重复建任务。任务子层级最多一层，简单通知不强制生成项目或 WorkPackage。

例如“周五交报告，PDF 格式，联系教务处”通常是一项提交报告任务；PDF 是格式，教务处是联系信息。“报名取消，改为提交摘要”需保留旧要求失效与新要求生效的关系。

### 5.2 必须保留的信息

| 语义 | 正确要求 |
|---|---|
| 动作/对象/执行人 | 分开表达，不能把人物名单当作执行人或把材料名称当动作 |
| 条件 | 前件、事实依据与 true/false/unknown 分开；未知不等于否定，不默认可执行 |
| 当前性与极性 | 要求、允许、禁止、背景、已完成、取消、替代分开；禁止项不能转成正向任务 |
| 材料与格式 | 名称、数量、格式、共享范围和归属完整；包装限制不是新的动作 |
| 完成标准 | 说明怎样才算办结，不能把输入材料或格式无条件当作已完成证明 |
| 修订与依赖 | 按动作和对象保留每个端点；跨对象不可合并；旧事实保留历史 |
| 事件、地点与信息 | 可以独立保存，信息通知不因有时间地点就必须创建任务 |
| 依据 | 重要字段有原文范围与来源版本；引用合法只是必要条件，仍要判断语义 |

预定义允许的别名和等价拆合。评分不能只接受某一句措辞或固定排列，也不能为了某个候选回答临时放宽。存在合理多解时记录可接受集合或未决项，标明完整/部分参照和作者身份。

### 5.3 时间与不确定性

- 区分截止、开始、结束、公布、可选计划时间；任务时间和独立事件时间经过同一时间策略。
- 同时保留 rawText、normalizedValue、timezone、type、precision、isAllDay、needsConfirmation 和关联对象；逐字时间正确但归一化或归属错误，仍是关键错误。
- 有日期无时刻保持 date-only；没有截止可确认无日期任务；相对时间绑定 referenceTime/timezone。模糊、未说明、冲突和待公布不可相互冒充。
- 中文数字、半点、上午/中午/下午/晚上/凌晨、跨午夜和跨月年须覆盖；不补七天后、18:00 或哨兵日期。
- “月底另行通知”首先表达公布安排和提交时间未知，不能直接造出月底提交截止；其具体 wire 表达须在新版本契约中明确。

### 5.4 安全与可用性共同验收

默认只勾选明确、当前有效且条件成立的行动。不能只靠少输出或全部 unknown 降低误建任务：同时报告 FN、未知/未选比例、补录负担、误勾以及正确无任务识别。单字段或单项错误应局部隔离；根结构不可解析才整份降级。

## 6. 四项主指标的统一含义

本节是后续测量的产品口径；不改写旧评分、未批准商业草案，也不新增遥测或真人研究授权。新运行必须绑定具体测量版本，不能假设现有组件已经完整实现以下要求。

### 6.1 首次整份建议正确率

在任何人工编辑、repair 或二次生成前，冻结首次完整输出。分子为任务/无任务判断以及关键时间、材料、条件、关系全部正确且无无据新增的来源数；分母为该批全部计划的合法来源单元。一次来源只计一次，传输或解析失败不删除。

同时列明完整参照覆盖率。部分参照可报告已核验字段，不能据此给整份 PASS；若整批不足以评价，则整份结论写覆盖不足，而不是将未知计为正确。合成 Development、已见回归、独立人工 Holdout、真人试次分别出表。

### 6.2 正确处置率

分子为在预注册时间窗内完成正确任务确认或正确无任务归档，且保存后独立读回一致的试次；分母为全部已开始的合法注册试次。放弃、失败、超时、未判定都保留并分栏；部分确认不算整份完成。

点击确认、写入成功、全部拒绝都不能单独证明正确。语义裁决与程序记录分别取证。

### 6.3 低修改正确处置率

现有 measurement 3.2 的历史口径为上述正确处置中未发生实质语义纠正的试次，分母仍为全部已开始的合法注册试次。这实际测量“零实质修改正确处置率”；保留原始字段、算法和历史输出，在新报告用这一准确中文名称。

实质纠正包括任务增删/拆合、动作对象、时间、条件、材料、完成标准、修订或依赖变更。纯文案美化和个人偏好单列。未来新增 low-edit-v2 独立口径，允许有限且已改对的字段编辑；字段数、编辑时间和禁止的结构变更在新试次前固定，与零实质修改率并列。候选提案为至多 2 个字段、主动编辑不超过 30 秒、无任务增删拆合及修订端点重接；这是待探索的产品假设，不是已验证阈值，也未接入当前 UI。缺少字段关联或时间时标未知，不计作低修改成功。不得回填旧结果或改名制造提升。

### 6.4 主动修改时间

累计用户实际编辑区间；页面隐藏、空闲中断、模型/系统等待分开记录。并报总处置墙钟时间、阅读核对时间、有效样本数、中位数和 P95，避免把阅读负担转移出去后声称省时。

失败或取消前已经发生的编辑仍是用户付出的时间，要保留原始事件和终止状态。未闭合或不可判定区间标缺失，不能填 0；成功样本耗时与全部试次负担分层报告，禁止只挑成功者。当前测量模块与此需求的差距须单独测试后才能宣称支持。

### 6.5 诊断与证据分层

- 辅助指标：Task TP/FP/FN、Severe/Major/Forbidden、时间/材料/条件错误、提取覆盖、误勾、Schema/引用失败、延迟、用量和成本。
- 首次正确率先反映建议质量；其余三项需要真实用户和独立正确性判断。工程回放只能证明流程与计算链路，自动化耗时不是真人主动时间。
- 报样本量、场景和不确定性，12 份合成来源只用于筛选方向，不宣称普遍提升。
- 首次快照不可被编辑结果覆盖，trial/source/candidate/operation 绑定并去重；局部本机完整性不宣称远程可信认证。
- 仅保存经授权的最小观察字段；本机日志不自动上传训练，费用无法观测写 NOT_OBSERVABLE，预算上界另列。

## 7. 技术路线与职责

沿用 React、TypeScript 严格模式、Vite、CSS、Lucide 与现有测试工具，优先复用现有领域和持久化层。

| 层 | 负责什么 | 主要验收点 |
|---|---|---|
| 本机读取 / OCR | 读全正文、页段顺序、范围与质量 | 不漏尾、部分提取诚实、来源定位 |
| 模型语义提取 | 根据完整语境提出行动、条件、事实和关系 | 不过拆、不漏关键义务、否定与修订正确 |
| 公共 adapter / 时间策略 | 转为同一可校验结构，保留不确定性 | 不默默补事实、时间/引用/两臂处理一致 |
| 评分器 / 参照 | 判断产品义务是否完整实现 | 正确答案可通过、关键反例必失败、等价表达公平 |
| 确认界面 | 发现问题、定位、修改、拒绝、部分确认 | 用户少找、少填、少跳转，失败可恢复 |
| Repository / DomainCommitPlan | 原子提交、历史、幂等与独立读回 | 刷新恢复、无重复、失败不污染正式数据 |
| 测量 | 区分首次质量、最终正确和真实工作量 | 分母完整、事件可追溯、未知不伪装为 0 |

实现前先建立语义→Prompt→wire→adapter→reference→scorer→UI 的对应表。某项产品语义在当前 wire 无法表达时，要登记缺口，再决定兼容扩展或暂缓该能力；不能通过隐式映射获得满分。

确定性代码处理可证明的结构、时间和状态约束；模型理解语言；独立人工给出正式语义参照。无需把全部中文含义写成关键词规则，也不默认增加第二个模型调用。

## 8. 确认体验要求

- 默认路径为“粘贴通知 → 核对建议 → 确认/归档 → 今日行动”；高级配置收起。
- 摘要卡优先显示动作对象、关键时间、材料、下一步和异常；详细字段按需展开，风险不能只靠颜色。
- 点击字段直接定位原文；不确定字段说明缺什么，不要求用户无差别检查每一项。
- 可以逐项编辑、拒绝、拆合、部分确认，关闭后保留草稿；重识别不覆盖已确认结果。
- 无日期任务可保存，无任务来源可归档；有事件或附属信息时仍保留其意义和依据。
- 保存状态明确区分处理中、成功、失败、已读回；失败后继续，重复操作幂等。
- 首页最多三项，任务卡的截止和完成操作清晰；月历只展示每日摘要，详情可展开。
- 深蓝与墨绿为主色，暖色用于风险；统一 SVG 图标。桌面双栏、手机单栏，320px 和 1024px 核心路径可用；键盘、焦点、Escape、减少动态效果和可跳过教程保留。
- 页面不把“实验回放”“模型录制结果”“本机数据”装成真实用户或线上服务。工程入口与旧库隔离。

## 9. 数据与服务要求

Workspace schema v8 保存来源版本、运行、草稿及各独立事实，派生推荐不成为第二事实源。旧 UI 兼容投影不能覆盖 canonical 数组。迁移须备份、校验、round-trip 和原子替换，无法确定字段保留 legacyData。

文件本体、图片和大二进制不进入 localStorage、工作区导出或 Git；默认本机读取/OCR后只发送当前用户确认的文字。只有明确授权的独立视觉实验可发送本次图片或所选页。服务凭证只在服务端，未配置能力诚实关闭。详细仍生效的边界见 [服务与数据边界](docs/governance/INTEGRATION_BOUNDARIES.md)。

## 10. 质量验证方式

以下是分别取证的工作方向，不是必须逐项等待的串行流水线。按 [分层推进规则](docs/governance/PROGRESS_POLICY.md) 确定每项工作的直接前提。独立质量验证和发布保留严格要求；开发回放、用户操作问题发现及适用工程改进可继续。

1. **工程可表达性**：正确 wire 能走通真实适配/评分/处置链路，关键错误 wire 必须被发现，零业务模型调用。
2. **Development 筛选**：允许使用已见与模型辅助匿名资料迭代；每次正式批次在派发前冻结，一次运行内不动规则。不能称为独立人工真值。
3. **独立 Holdout**：候选和规则冻结后接入开发者未见的独立标注资料；人工 A 标注、B 复核，有冲突裁决和信息隔离。缺人时只完成准备，不伪造独立性。
4. **真人效用**：在获准的研究中比较正确处置、实质修改、主动时间和放弃率，平衡难度和顺序，避免熟悉同一通知带来的假收益。
5. **发布验证**：按被批准的范围、阈值、浏览器矩阵、运行与回滚协议验收，另行取得部署授权。

未批准的 [商业验证契约](docs/recognition-optimization/COMMERCIAL_VALIDATION_CONTRACT.md) 保留原样，其九格式、两批 Holdout、样本量和数值门槛仍是全范围商业提案。它不阻止小规模探索，但探索结果不能替代正式门。未来若缩小首发范围，需新契约和新证据，不改旧 FAIL。

### 10.1 面向迭代的分层判断

- 工程完成：相应功能、错误恢复、保存读回及必要测试通过，就交付该功能。模型候选未晋级不能抹掉工程成果。
- 开发观察：报告同口径的改进、退步和覆盖缺口；没有全面优势也可决定继续修哪一个缺口。“整份净增两份”是旧 12 份批次筛选线，不是所有进展的最小单位。
- 探索体验：单独获授权后，可用已核对匿名材料和人工确认流程找操作痛点；无需先宣称模型全面超过基线。模型故障必须可见、可拒绝，引用错误相关项不可确认，来源不丢失。探索不证明泛化或生产安全。
- 独立验证：正式质量比较仍使用冻结候选、独立材料、真实人工标注/复核、预注册分析；真实收益需同时观察正确处置、修改负担和放弃。
- 发布：按明确支持范围验证。不会因一个综合分数提高就放过确定的严重错误；不支持场景须在进入时说明，保留来源和人工处理入口，不得为了抬分从分母偷偷删去。

## 11. 后续推进路线

| 工作包 | 要做什么 | 可交付的结果 | 决策边界 |
|---|---|---|---|
| W1 契约闭环 | 修复信息 scope 口径和独立事件时间漏检，裁决包装/完成标准、待公布时间；补正反例 | 新版本对应表、评分器/适配器、匿名回归与限制说明 | 先用已见工程资料，不为每个修复重造盲测；旧 D7 仍保留 |
| W2 产品工作量闭环 | 复核无日期/无任务/部分确认、字段依据、失败恢复；检查计时是否保留失败编辑负担 | 隔离真实页面可操作、保存读回及浏览器证据，测量差距报告 | 仅工程回放，不得计算真人转化率 |
| W3 Development 候选筛选 | 固定新版与 Candidate03 的比较对象、数据、完整参照、门槛和预算 | 审查通过的请求身份与新授权卡；获授权后结果包 | 新付费调用需单独明确授权；开发筛选不等于泛化 |
| W4 独立质量验证 | 候选冻结、独立人工资料、复核与裁决，保护未见集 | 独立 Holdout 证据及场景分层错误 | 缺独立人工则等待此结论，其他本地工作可推进 |
| W5 真人体验验证 | 注册试次、真实操作、独立语义判断、平衡比较 | 四项主指标、缺失/放弃及不确定性报告 | 单独授权；规模服务于声明强度，不把探索研究当商业通过 |
| W6 首发决策 | 根据证据确定发布范围、配额、成本、服务/隐私和回滚 | 明确支持范围、验收结果和发布申请 | 默认候选、Preview、Production 各按对应授权执行 |

W1 与 W2 可在同一已授权大工作包连续推进；W5 的匿名探索准备也可并行于 W3/W4。W5 正式真人研究仍按授权执行，W4 独立证据仍独立取证。当前具体执行顺序以 [活动路线图](docs/governance/PROJECT_EXECUTION_ROADMAP.md) 为准，上表为职责而非永久串行门。模型调用、真实数据或发布边界分别审批。计划不等于已经完成。

## 12. 当前迭代的验收与拒绝条件

- 每轮首要验收由当前最多三类用户失败决定，交付明确修复、真实证据及限制；不长期绑定 D7 或其他旧阶段编号。不能仅凭单元测试数量宣布识别提升。
- 只改文档或独立工具时，按 AGENTS 的影响级别验证；产品代码交付跑定向测试及 lint/test/build，交互变化有浏览器证据。
- 任何新出现的严重错误、关键漏项增加或未解释的评分差异，都要进入错误分析；是否晋级严格执行该次预注册规则。
- D6/D7 原有拒绝、失效、历史失败与调用账本保留。新的评分契约只能产生新报告。
- 功能交付、研究通过与可发布是三个不同状态。工具缺失和无独立标签不掩盖，也不让无关工作无期限停摆。

## 13. 暂不增加的复杂度

在四项主指标没有可信证据前，不优先做模型大范围调参、自动多模型复核、复杂个性化、全格式一次覆盖、账号支付或额外装饰页面。新模块要说明它消除哪类真实错误或用户操作负担，以及怎样验证净收益。
