# 识别优化分层推进规则 1.0

生效：2026-09-28。授权依据：用户要求审查过严门槛、全面优化效率并参考相似项目。本规则只面向未来工作，不修改 D11 或更早批次的门槛、Expected、分母、成绩及结论。

目标：每轮减少通知处置中的真实错误或操作负担，并让已经完成的改进可以单独交付。四项产品主指标继续保留，尚不可观测的指标如实记录。

## 1. 五种状态分别报告

| 判断 | 最少需要什么证据 | 不必等待什么 | 能做出的结论 |
|---|---|---|---|
| 工程交付 | 涉及的正确/错误路径测试；交互改动有实际浏览器及保存读回 | 新候选全面胜出、独立人工 Holdout | 该功能已修复或链路已运行 |
| Development 观察 | 已知数据角色、两臂同口径、完整分母、可复核错误与争议 | 全场景零错误、固定净增两份 | 在列明的开发场景有改进/退步/无法比较 |
| 探索试用准备 | 匿名材料、人工确认、错误可见、来源保留、相关项安全隔离、测量可用 | 独立泛化结论、全部开发难例通过 | 可申请小范围探索；还没有真人数据 |
| 独立质量/真人效用验证 | 独立参照、冻结候选/口径、对应真实试次、授权和缺失报告 | 与验证声明无关的全格式/商业功能 | 所声明范围内的独立质量或观察收益 |
| 默认替换/发布 | 预先确定支持范围及质量门、生产链路、回滚和明确授权 | 与首发范围无关的功能 | 仅按获准范围发布 |

这里的“不必等待”不会自动授权模型调用、招募、对外发送、换默认或部署。独立验证和发布的具体阈值仍在正式实验前确定。

## 2. 旧门槛应该如何使用

D11 的五条门槛全部保留。它们能决定这次 Candidate15 是否按旧协议晋级，不能用于否定 D10 的事件保存改进，也不能禁止用录制输出验证失败恢复。

后续不再自动复制“12 份×2、两臂全有效、零错误、净增 2”作为一切工作前提。12 份中净增 2 等于 16.7 个百分点，这是该批开发筛选的较大跨幅，不是可以证明统计可靠性的统一标准。

未来开发批次用以下决策表，派发前写入该批 manifest：

| 观察 | 开发决定 | 后续工作 |
|---|---|---|
| 相关工程反例修复、真实错误减少，其他重要项未退步 | 保留改进并继续验证 | 可冻结待独立验证候选；不自动替换默认 |
| 局部改善伴随其他退步 | MIXED，明确取舍 | 优先修退步，或预先声明受限范围；完整报出失败与回退成本 |
| 无可信收益 | 修根因/换假设 | 不再靠加审计或换编号继续相同尝试 |
| 评分器错误、参照争议或比较不公平 | EVIDENCE_INCOMPLETE | 只停相关质量结论；两臂录制回答离线复核，其他工程继续 |

不采用一个总分自动抵消严重错误。当前可执行义务 FN、无据新增、错误关键时间、条件与修订误用分别报告。范围限制必须能在产品入口/结果中执行，并记录回退量；不能看了输出才挑容易的来源或只算成功者。

基线的解析或引用失败属于基线的确定失败，应保留分母并比较；未来不因基线有错误就自动否决另一臂。候选自身的无效项、漏项和回退负担仍照实计入，不因局部隔离而从首次质量指标中消失。新规则必须在新输出前绑定，不能用于追溯改判 D11。

## 3. 停止操作的最小范围

| 问题 | 停止 | 继续 |
|---|---|---|
| 评分器异常 | 使用该评分器的质量比较、新冻结正式比较 | 本地修复、两臂事后诊断、隔离工程回放 |
| 某来源语义参照有争议 | 该来源整份正确裁决；缺口报告保留该来源 | 无争议字段诊断、其他来源分析；不能把整批率算在缩小分母上 |
| 引用不存在/对象关系错误 | 受影响项的正式确认和自动执行 | 原始建议显示、错误提示、人工编辑、无关联安全项（需有隔离证明） |
| 缺独立人工 | 独立真值/泛化声明 | 单作者 provisional 开发、模板、工具、探索方案 |
| 缺真人试次 | 真人四项指标与省时声明 | 实际产品链路及测量工程测试 |
| 历史断言检查旧活动文档或旧账本末尾 | 将该检查当作当前开发总门 | 保留旧失败；用版本化历史前缀/原字节/哈希链核验 |
| Secret、预算、发送状态或旧库安全不明 | 对应危险操作 | 与之无关的只读和隔离本地工作 |

工具 `scripts/recognition-progress-policy.mjs` 将阻碍分配到直接依赖的工作；没有列出阻碍不等于通过验收，更不等于授权。

## 4. 评分与测量需要修正的口径

1. 整份严格正确率继续作为质量结果，同时给出任务/关键字段/场景维度，不用一个“全错”遮住修复方向。
2. 精确引用合法性与语义正确性分开。证据 ID 集合不完全一样，不能直接推定意思错误；下一评分契约需先定义必要证据、可接受补充证据和错误归属，禁止无条件放宽为任意 superset。
3. 空匹配必须稳定返回 TP=0、FN/FP；不能抛异常。合理别名、顺序和合法拆合用同一契约验证两臂。
4. `Forbidden` 只在来源存在禁止/失效条件且输出构造当前可执行义务时，经可追溯裁决使用。旧 v6 的“未匹配可执行任务”计数仍保留原名在历史结果中；新的诊断另标注其真实含义，不冒充已判定的禁止行为。
   任务存在性的 TP/FP/FN 与匹配任务的字段正确率也要分开。旧 v6 只有所有字段通过才计 TP，但已匹配的错误任务不计 FN；新契约需明确计数单位并验证守恒，不能直接拿旧值解释标准任务召回率。
5. “低修改”不能永远等同“零修改”。现行 measurement 3.2 的零实质修改指标保留；未来 low-edit-v2 另列阈值和版本，在真人观察前冻结。不得把阈值变化当算法改进。
6. 只读重评分与新模型评测分开。只修改评分代码时先复用全部原始回答，不再为获得同一份输出花钱。输入/候选变化后必须取得新输出才可宣称候选效果。

## 5. 收敛工程节奏

每个工作包最多集中三类高价值根因；按“复现→实现→定向反例→必要全量检查→真实交互证据→提交推送”连续完成。无需每修一个小步骤重新申请授权。

本地先用已见资料。当前 12 份合成 Development 可反复用于开发；新增工程反例检验规则而非凑高分。每轮都重造 12 份、重写所有手册和新增复杂框架不是默认流程。

活动入口只有 PRD、AGENTS、CURRENT_CONTEXT、路线图和一份下一工作包；日志记录历史，不重复承担当前指令。一个独立视角复核足够；只有新发现影响当前边界时追加复核。

不把严格门槛挪掉后直接发布。先把“做出了什么”“哪里更好”“哪些错误仍影响用户”“哪些证据还缺”分别说明，才能有效推进。
