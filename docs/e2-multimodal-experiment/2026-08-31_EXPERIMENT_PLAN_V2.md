# E2-MM 多模态输入消融实验修订计划 V2

**应用基线**：`v2.0.0-beta.1-rc.4`（保持不变）

**实验分支**：`codex/e2-multimodal-recognition-exp`

**实验模型**：三臂统一为 `deepseek-v4-flash-vision-exp`

**状态**：方法与实现待冻结；冻结前禁止对 V2 材料调用模型
**日期**：2026-08-31

## 第一性原理问题

本实验要识别的是“输入中增加图片或 OCR 文字是否提供了稳定的增量信息”，不是比较两个不同模型。因此唯一允许变化的处理因素是输入模态；模型、Prompt 结构、temperature、输出 Schema、参考时间、评分器和限流策略必须保持一致。

| Arm | 唯一输入正文 | 固定模型 | 目的 |
|---|---|---|---|
| T | 冻结的本机 OCR 文字 | `deepseek-v4-flash-vision-exp` | 估计纯文字路径 |
| I | 原图/选定页面；不含 OCR 正文 | `deepseek-v4-flash-vision-exp` | 估计纯视觉路径 |
| IT | 与 I 相同的图 + 与 T 相同的 OCR 文字 | `deepseek-v4-flash-vision-exp` | 估计互补信息 |

I 臂的 HTTP 请求、Worker Prompt、上游消息和 Worker 归一化均不得包含 OCR。冻结 ground truth 只允许在模型调用完成后的离线评分器中出现。

## 为什么 V1 不能作为正式比较

- V1 的 T 臂使用稳定文字模型，而 I/IT 使用视觉实验模型，不能把差异归因于输入模态。
- V1 的 I 臂把 OCR 保留在 Worker 后处理证据核验中，不是严格的图片版消融。
- V1 评分器会给“预期与预测任务都为空”的样本记满分，并把无实体、无证据记作 evidence 满分。
- `mmu1-01` 已被密钥刷新连通性测试调用，已不再未见。

因此 V1 只保留为故障与方法审计证据，不进入 V2 正确率表，也不得用于上线结论。

## V2 数据冻结

- 36 条新生成的匿名合成材料：截图、照片、扫描页各 12 条；精确文本、日期、编号、渲染随机种子和文件哈希均不同于 V1。
- 12 个独立情境家族，每个家族有截图/照片/扫描三种渲染。统计推断按情境家族进行 cluster bootstrap，不能把 36 条当作 36 个完全独立语义样本。
- 先生成材料，再在本机完成 Tesseract OCR，随后写入只读冻结清单；冻结文件逐例绑定 source、image、expected、OCR 哈希。
- 冻结提交并推送后才能进行第一次 V2 模型调用。Expected 与 ground truth 永不发送给模型。

## 评分与失败规则

主指标为 Task micro-F1、Major Correction Rate、Complete Case Accuracy；次指标为材料、时间点、事件、requires-action、禁建任务和证据有效率。

- 预期任务和预测任务都为空时，Task F1 为 `NOT_APPLICABLE`，不得记 1。
- 有预测实体但没有证据时，Evidence Validity 为 0；没有预测实体时为 `NOT_APPLICABLE`。
- 自动纠正操作数只是修改负担代理，不能写成用户修改时间。
- 人类修改时间在真实参与者完成可编辑确认流之前必须保持 `NOT_RUN`。
- 任一臂出现请求、认证、计费、限流、Schema 或模型不一致失败，该臂的质量汇总全部失效；失败不得从分母删除或静默重试。

## 预注册合成门槛

V2 只有在 108/108 次请求均由冻结模型完成时才计算可用于比较的质量指标。IT 必须同时满足：

1. Task F1 分别高于 T、I 至少 0.03；
2. Major Correction Rate 分别低于 T、I 至少 0.05；
3. cluster bootstrap 95% 区间不得指向相反方向；
4. Severe/Forbidden、Evidence、TimePoint、Material 不出现足以抵消主收益的退化；
5. 三臂返回模型均严格等于 `deepseek-v4-flash-vision-exp`。

即使全部通过，也只表示“值得进入真实材料与人类计时验证”，不授权替换稳定模型或上线。

## 对抗性审查面

- OCR 泄漏：在 I 请求中注入禁止字段应在访问上游前失败；测试必须检查整个请求对象，而不只检查消息文本。
- 空输出套利：无行动材料、全请求失败、部分失败都不能产生虚高质量分。
- 模型混用：返回模型与结果模型任一不一致即记配置失败。
- 模板伪重复：配对分析按 case，置信区间按 12 个情境家族聚类。
- Prompt 注入：材料中的“忽略规则、删除任务、转账”等只能作为不可信正文，禁止成为任务。
- 隐私越界：只发送本次原图/选定页和按臂允许的文字，不发送整个工作区、文件库、历史或 Expected。
- 发布越权：实验 Preview、RC.4 Preview 和 Production 分离；结果不能直接创建正式任务。

## Stop / Go

1. 工程回归、全量质量门槛和独立 Preview 部署通过；否则停止。
2. 生成 V2、完成本机 OCR、写入并提交冻结清单；否则禁止模型调用。
3. 先运行 1 case × 3 arms 的 V2 传输冒烟。只验证契约、模型和隔离，不纳入质量表。
4. 冒烟通过后，使用其余仍未见 V2 材料进行正式配对运行；被冒烟使用的 case 从正式质量样本排除，或另行生成替代 case。
5. 结果完成后进行独立对抗性审查；任何高严重度问题或 A–J 未完成，结论均为 `MULTIMODAL NOT PROMOTED`。

为保留完整 36×3 正式样本，本轮不在 V2 上另做模型冒烟；部署契约由 Mock 回归与 V1 连通性诊断确认，V2 冻结后直接执行一次、零评估器重试的正式运行。
