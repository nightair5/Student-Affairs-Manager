# 直接图片识别第二次未见集复验结果

## 结论

**不值得按当前形态上线。** `deepseek-v4-flash-vision-exp` 直接看图片时，任务级 F1 为 **71.29%**，与上一批的 **71.58%** 基本一致；两批合计 72 份的任务级 F1 为 **71.43%**。这说明约七成的任务结构识别表现可以复现，但不等于七成材料可以直接使用。

更接近真实使用风险的指标没有过关：36 份材料中 **0 份整份完全正确**，时间点 F1 为 **0%**，36 份都需要重大修改，平均每份需要 3.56 次自动增删改操作。模型还在 22.22% 的材料中生成了不该生成的任务。因此它只能继续作为显式授权后的待确认实验建议，不能替换稳定识别链路。

## 本轮设计

- 第三批全新匿名合成未见材料 36 份：截图、照片、扫描件各 12 份。
- 与前两批的 source hash、image hash 重合均为 0。
- 数据、OCR 和 Expected 在首次模型调用前冻结并提交。
- 只运行 I 臂：发送原图和最小标题/参考时间信息；不发送 OCR 文字、Expected 或 ground truth。
- 36 次顺序调用，零评估器重试；本轮 36/36 均成功。

## 正式指标

| 指标 | 本轮 V3 | 上一批 V2 直接图片 | 解释 |
|---|---:|---:|---|
| 任务 Precision | 87.80% | 97.14% | 生成的任务中有多少匹配 |
| 任务 Recall | 60.00% | 56.67% | 应识别任务中找回多少 |
| 任务 F1 | 71.29% | 71.58% | Precision 与 Recall 的综合 |
| 整份完全正确率 | 0% | 0% | 是否可以不修改直接确认 |
| 时间点 F1 | 0% | 0% | 截止时间等结构化时间识别 |
| 重大修改率 | 100% | 100% | 是否需要实质性人工纠正 |
| 不应生成任务率 | 22.22% | 8.33% | 把非任务内容误当任务 |
| 平均自动纠错操作 | 3.56 | 3.42 | 仅为修改负担代理，不是用户用时 |

按材料类型看，本轮任务 F1：截图 **64.52%**、照片 **68.57%**、扫描件 **80.00%**。每类只有 12 份，不能据此宣称扫描件普遍优于照片或截图。

## 第一性原理判断

产品要解决的不是“模型能否读出一些字”，而是“用户能否更快、更安全地得到可确认的任务建议”。当前模型虽然能识别不少任务与材料，但核心事实仍会漏：任务召回只有 60%，时间点完全未对齐，整份材料没有一份无需修正。用户必须逐项核对，错误还可能看起来很像正确答案，因此不能仅凭 71% 的 F1 上线。

真实用户修改时间本轮仍为 **NOT_RUN**。自动纠错次数不能冒充用户秒数；在真人盲测证明节省时间之前，不能声称它提高了效率。

## 上线判定

维持 **DO NOT LAUNCH**：不替换 RC.4，不改变默认“本机 OCR/解析后只发文字”，不直接创建正式任务。后续只有在真实匿名未见材料、真人修改时间、隐私安全和浏览器 A–J 验收均通过，而且多模态稳定优于文字基线时，才重新讨论上线。
