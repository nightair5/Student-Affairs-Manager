# E2-MM 未见材料三臂实验结果与上线审查

## 结论

本轮结论为 **DO NOT LAUNCH**。T（本机 OCR 文字）、I（图片）与 IT（图片 + 同一份 OCR 文字）均没有产生一条可评分预测；安全诊断确认三臂都被 DeepSeek 上游鉴权拒绝。正确率、完整案例准确率、Major Correction、配对差值和用户修改时间因此全部不可计算，不能写成 0 分，也不能从本轮推断任何一臂优于另一臂。

RC.4、现有稳定模型与 Production 保持不变。实验只发生在独立 Worker `student-affairs-manager-multimodal-exp` 和分支 `codex/e2-multimodal-recognition-exp`。

## 冻结输入与可复核边界

- 冻结集：36 条匿名确定性合成材料；截图、照片、扫描各 12 条。
- Dataset SHA-256：`015aff593834471bc5f480dc6de544eef461d95a66344b21949270659372aae5`。
- OCR Bundle SHA-256：`ad67306d1c620096416cb4908319f18a9503b74c58d7072007d077b83ef82491`。
- Ground Truth 未发给模型；图片与原始 checkpoint 保留在 git-ignored `.evaluation-cache`。
- 该数据只是假设检验前的 synthetic proxy，不是“真实未见用户材料”，不能单独支持推广。

本机 Tesseract.js OCR 的平均字符错误率为 19.39%；截图 28.30%、照片 14.69%、扫描 15.17%。这是 OCR 层可观测误差，不是任务识别正确率。扫描均值还受到单个 85.21% CER 难例影响，说明按介质报告比只看总平均更重要。

## 用户修改时间

真实用户修改时间为 `NOT_RUN`。没有参与者完成“查看建议—编辑—确认”流程，因此没有秒数可报告。自动化的增删改操作数只能作为校对负担代理，且本轮因 0 条有效预测同样不可计算；它不能替代用户时间。

## 浏览器对抗性检查

在独立 Preview 使用匿名合成截图完成了以下现场检查：

- 图片完成本机 OCR 后，发送图片开关默认未选中。
- 开关旁明确列出会发送的当前 1 张原图、OCR 文字、来源标题、参考时间/时区和限量上下文，也列出不会发送整个工作区、其他文件与历史全文。
- 主动打开开关后更换文件，授权自动恢复为未选中。
- 默认文字版遇到上游鉴权失败时，Source 被保留、任务数为 0，并提供本地规则重试和手工补充。

同时发现一个发布阻断缺陷：`/api/deepseek/status` 只证明 Secret 存在，页面却显示“DeepSeek V4 Flash 已连接”；真实 T/I/IT 调用均已证明鉴权失败。配置存在不能等同于认证成功或能力接通，这违反诚实状态原则。A–J 全量浏览器、存储/导出、PDF 页码、响应式、键盘、reduced motion、Chrome/Edge 交叉验收仍未完成。

## 第一性原理判断

这个功能只有在“减少错误”和“减少用户核对成本”的收益稳定大于新增的图片外发、延迟、费用、复杂度与误导风险时才值得上线。本轮能确认的只有工程隔离和部分 consent 行为，核心收益没有任何有效观测；相反，鉴权不可用和连接状态误报是已经观测到的确定性风险。

因此上线决策不是“证据不足，先小流量试试”，而是 fail-closed 的“不上线”。小流量也会把未经验证的隐私外发和错误状态交给用户，不能替代实验门槛。

## 恢复实验的最短条件

1. 提供一枚真实有效、未过期、具备目标模型权限和可用额度的 DeepSeek API Key；Secret 仍只写入独立实验 Worker。
2. 先以新的 Run ID 运行 1 例 × 3 臂烟测，三臂都必须产生有效 `RecognitionResult 2.0`；失败不得隐藏重试。
3. 再运行冻结的 36 × 3 合成代理；随后使用互不重叠的真实匿名未见批次复验。
4. 由真实用户完成平衡顺序的编辑确认流程，采集实际修改时间。
5. 修复“已配置即已连接”误报，并完成隐私、安全、A–J 浏览器验收与 RC.4 稳定性门槛。

任何一步失败，稳定模型、RC.4 与 Production 继续不变。
