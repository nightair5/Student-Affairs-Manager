# 限制访问测试版：负责人检查清单

2026-10-18核验：preview只有`DEEPSEEK_API_KEY`，缺`PREVIEW_ACCESS_CODE`，本轮未部署；没有本轮地址或部署版本ID。请勿把旧自定义预览站点当成本候选。口令只由负责人自行通过Cloudflare Secret流程配置，不发给Codex、不写Git。

1. 部署前确认两个Secret名称都在preview环境，记录候选Git SHA及当前部署版本。只用`wrangler deploy --env preview`输出的workers.dev地址，不改域名或正式路由。
2. 打开地址：未登录应只看到口令页；静态资源和API也须401。输入负责人自设口令，应进入首页；错误口令应被拒绝，连续错误应429。
3. 粘贴一条去标识的简单通知并主动提交：首次方案应列出做什么、截止、材料、去向及真正待定处。没有依据的事实不应被补成确定值。
4. 查看原文依据；正确时点一次接受。错误时先修改或逐项拒绝；无任务的通知可以只保存事件或信息，不创建空项目。
5. 查看今日、任务中心、日历和来源：数量、对象、时间和依据应一致。个人安排与原截止分开，不能提前排进尚未开放的办理窗口。
6. 刷新并重新打开浏览器：已确认内容应保持，待确认草稿仍在，不出现重复任务。站点数据只在当前浏览器与域名，不会自动同步到正式站点。
7. 从项目页导出JSON并妥善保存；先备份当前数据，再在隔离测试库导入，核对任务、事件、材料和时间。不要拿旧用户库做演练。
8. 问题请记在本文件下方，只写去标识原文、操作、预期/实际、时间、浏览器和截图，不含口令。回退前保存当前JSON；`wrangler rollback <已核验仍有口令保护的版本ID> --env preview`仅用于受保护版本。本轮没有部署，故没有可填的本轮版本ID；首次受保护发布不能回退到旧无口令版本，应重新部署保留访问保护的已验构建。
