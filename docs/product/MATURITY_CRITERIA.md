# 产品成熟标准 1.0

状态：2026-10-15依据负责人“按审查结论执行、固定成熟标准、不扩范围”的授权建立。它是后续产品验收的固定目标；当前未达标，也不授权真人、默认替换或发布。历史商业契约与旧成绩不改。

## 固定范围

成功形态：放入通知 → 看完整方案 → 一次接受 → 按安排行动。

范围沿用PRD的文字主流程：粘贴、TXT、Markdown和已经可靠提取的PDF正文；作业、报名、材料提交、会议活动、更正/取消、条件/资格、共享材料、模糊/待定时间、纯信息。单/多事项、长正文及组合条件都留在该范围，不能看到失败后删去。文件提取不完整须显式说明，仍记失败或部分；不冒充完整识别。

能力包括普通确认、今日/任务/日历/来源/个人安排、刷新、失败恢复、导出导入和v8安全升级。账号、微信、云同步、自动外发和新增OCR能力不加入本标准。保留既有入口与诚实的人工补充路径。

## 四项固定要求

| 方向 | 固定目标 | 如何判断 |
|---|---|---|
| Q 首次质量 | 声明范围内，人工编辑或二次生成前整份关键事实正确至少90%；固定验证集中用户首次建议严重错误0，已知严重漏洞已解决 | 任务/无任务、事件、时间角色/值、材料/渠道、条件、修订/依赖及来源一起核；标题和说明可能改变义务时也需裁决。未决/失败/未知保留分母，不给完整 |
| E 用户负担 | 全部合法使用试次中，至少90%能零实质事实修改完成正确处置；最终正确处置至少95% | 增删任务、改对象/时间/条件/材料/关系均属实质修改。参与意愿、个人偏好单列；简单来源提交后一次接受，复杂来源集中处理真实例外。提示须能定位真实缺口，误提示和放弃也记录 |
| P 主流程 | 下方有限矩阵通过；10个以上来源、跨两周的隔离工作区结果一致 | 数量、值、精度、依据、归属及关系需实际浏览器和独立读回一致；单测、HTTP成功或保存成功不替代语义正确 |
| S 数据安全 | 有限故障/升级矩阵中0正式数据丢失、半份写入、无意重复或静默覆盖；失败有保留输入、重读或备份恢复出路 | 旧合成数据升级前快照、全图/往返验证、原子写入；快照配额/损坏不得继续覆盖；真正旧用户库验证与部署另授权 |

严重错误固定为：把取消/禁止事项建成可执行任务；编造截止；把办理窗口/活动起点当截止；作废截止重新生效；丢失来源；覆盖已确认数据。关键遗漏、错归属、错误资格也逐例报告，不以总分抵消。

模型原答与程序首次建议分开。原答有错误但被有依据的程序纠正，可以改善产品；原答严重错误为0不是独立的成熟硬门。程序不得把正确事实改错或用全部拒绝、全部未知得到表面安全。固定测试集中0观察到严重错误不等于现实风险为0。

## 有限产品矩阵

1. 粘贴、TXT、Markdown、文本PDF读取范围可见；不完整提取诚实提示。
2. 简单来源一次接受；可选参加保留意愿；未知资格与前置等待分开。
3. 逐项拒绝、部分确认、坏关系局部阻断；无任务来源保留事件/信息。
4. 今日、任务、日历、来源档案与个人安排消费同一事实；原截止和个人计划分开。
5. 多来源安排不重叠固定活动、遵守窗口/依赖；不可行有说明。
6. 刷新、关闭重开、重复确认不丢失、不重复。
7. 检查点失败、正式事务失败、提交成功但读回失败的恢复分别正确；后者只重读。
8. JSON导出导入全部canonical字段往返一致；ICS不制造截止或外部写入。
9. 合成旧数据含来源、草稿、任务、事件、材料、时间和计划；升级快照及恢复正确，配额/损坏故障不覆盖。
10. 320px、1024px核心路径可用；键盘、焦点、关闭弹层和中文文案可用，无内部ID/ISO暴露。

无影响且构建关联明确的既有证据可复用，并标明日期和范围。新增相关问题只补受影响项，不每轮重做全部矩阵。

## 证据规模和状态

- 工程可交付：定向正反例、旧raw回归、受影响产品链、适用检查通过，即可交付可回退修复。缺独立资料或真人不阻挡工程。
- 首次质量可验证：后续冻结完整产品版本和判分规则，至少50份未见真实公开或获授权通知，九类各至少3份，其余按预先固定的来源计划分配；按来源/场景/长度分列。参照由被测实现之外建立并经独立人工复核；开发者/模型自审只属provisional。看过的材料进入回归，不再次叫未见。
- 持续使用可验证：取得相应授权后，至少5名目标学生持续14天、累计至少50个合法来源试次；按同一口径观察正确处置、修改、阅读/等待/主动时间、退出和恢复。缺少观察数据时写“尚未验证”，不填0、不冒充成熟。
- 成熟：上述固定范围的Q/E目标和P/S矩阵均有相应证据，且没有未解决的已知严重问题。当前仍是工程交付和开发诊断状态。正式上线另需负责人授权。

50份、5人和14天是本产品的阶段性验收设计，不是行业认证，也不证明所有校园场景的总体风险。不得仅凭开发集过线宣称长期成熟。

## 防退步及停止规则

固定一套产品版本：生成输入/Schema、公共转换、时间策略、页面与判分版本。程序改动先用同一批原raw比较；生成改动再用冻结的新输出验证。原答、转换、首次页面、人改和计划分别保留。

每个补丁检查旧完整来源是否退步、正确关键值是否被改写、是否新增严重风险，并列出逐例变化。评分状态没变但选择/归属/时间改变，也必须审查。正确事实不能为修另一例被静默牺牲。新生成版本整体与真实公开子组均不退步且无新增严重风险，才考虑采用；单次随机波动不证明机制收益。

同一发生层问题两次修复无收益，转做接口分析；没有新证据不继续加提示词。完成当前缺陷和防回归就结束工作包，不为“成熟”扩功能或用满调用预算。

本标准不在每轮加码。改变范围、公式、阈值或证据要求必须另起版本、记录理由，保留旧结果并报告双口径；未达标只限制相应成熟声明，不抹掉已交付工程成果。
