# P7 Recognition Quality Validator Report

## Verdict

P7 Validator gate: **PASS**.

`recognition-quality-2.2.0` was evaluated against 80 frozen, exposed diagnostic outputs generated by `deepseek-v4-flash` with `recognition-2.4.1` and `recognition-pipeline-2.2.1`. The Validator only reports issues; it does not create or rewrite RecognitionResult entities.

The historical E2.5 Validator result (Micro Precision 50%, Recall 16.22%) is retained as prior evidence. It is directionally comparable, but not an exact paired delta because P7 uses a newly frozen 80-case multi-label set and the expanded 13-code contract.

## Contract coverage and limitation

The real 80-case set has no positive `POSSIBLE_FALSE_PRECISION` or `OVER_FRAGMENTATION` observation. Their detection paths are therefore covered by isolated synthetic contract tests, but no empirical Precision/Recall is claimed.

The eight `INVALID_EVIDENCE` labels represent strict expected-fact evidence coverage gaps even though the emitted evidence quotes are structurally valid substrings. A Validator that cannot read expected answers cannot reliably infer those fixture-specific minimum counts. The production-safe Validator therefore detects missing, dangling, or non-source evidence, but does not guess expected-fact coverage. This class remains a known recall gap and must not be described as solved.

`repair.ts` changes in this phase are compatibility-only issue-code mappings required by the renamed Validator contract; no new repair algorithm or extra model call was introduced. Repair benefit and harm remain unproven until the separate P8 ablation.
