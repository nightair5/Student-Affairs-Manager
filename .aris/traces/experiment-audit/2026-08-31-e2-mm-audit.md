## Adversarial code counterexamples

1. `safeF1(0, 0, 0)` returns precision/recall/F1 `1`. A truthy completed result with empty expected and predicted entities can therefore receive perfect entity scores.
2. Aggregate evidence validity returns `1` when completed outputs contain zero evidence. This is validity-over-produced-evidence, not evidence coverage.
3. A completed empty no-action case can obtain entity F1 `1`, complete-case accuracy `1`, zero correction operations, and evidence validity `1` despite producing no evidence.
4. A selective-success run may report perfect completed-only quality when one easy case completes and the remaining cases fail. Request-failure rate is separate, while paired bootstrap silently excludes noncompleted pairs.
5. The I-arm runner puts frozen OCR in `body.content` for every arm. The Worker omits it from the upstream image-only prompt, but uses it in post-model normalization/evidence validation. “Image-only” is true only at the upstream-message boundary, not end-to-end.
6. HTTP/auth/upstream/schema-invalid and missing-result conditions converge on runner status `request_failure`; the scorer cannot report the pre-registered transport, invalid-output, semantic, severe-error, and scoring categories independently.
7. Resume treats any existing observation, including a failure, as completed work and skips it. This preserves no-hidden-retry evidence but prevents a same-label policy distinction between retryable transport failures and final semantic results.
