### Material findings

1. High: frozen scorer cannot score zero action/object matches.
assignments() creates an all-null mapping, but the seeded reduction can retain {map: []} on a tie; the following code then dereferences actual[undefined].id (scripts/score-candidate15-contract.mjs:23-31, :71-74). The three resulting TYPE_ERROR cases appear at SCORING_RESULTS.json:3136-3157, :3196-3217, and :6998-7019. The wrapper catches these as SCORER_EXCEPTION and prevents promotion (scripts/score-candidate15-d11.mjs:49-60), so this invalidates complete quality metrics without falsifying the rejection.
Minimal future fix: create a new scorer version whose reduction starts from evaluated[0], then test zero predictions, only nonmatching predictions, multiple expected tasks, and empty-reference sources. It should return finite FP/FN counts and complete:false, never throw. Preserve D11 unchanged.

2. Medium limitation: the references support Development screening only.
The reference package declares SINGLE_AUTHOR_MODEL_ASSISTED_NOT_INDEPENDENT_HUMAN and every source is FULLY_SEEN_D5_SYNTHETIC_DEVELOPMENT (REFERENCES.json:2-11). D10 freezes 12 sources, 12 arms each, and 6 AB/6 BA with common parameters (MANIFEST.json:3-29), so there is no sign of post-output reference tailoring or asymmetric runtime configuration. This is acceptable proxy truth for debugging, but cannot establish general candidate superiority.

3. Low machine-consumption risk.
AUDIT.json uses PASS_ACCOUNTING_AND_IDENTITY_WITH_SCORING_FAILURE (AUDIT.json:2-4). Humans can read the qualifier, but a consumer using a PASS* prefix could misclassify it. Future artifacts should separate accountingStatus, scoringStatus, qualityStatus, and overallStatus. The future audit should also store the exact SCORING_RESULTS.json SHA.

4. Low future robustness issue.
The scoring wrapper hardcodes transportStatus:'HTTP_200' and teachingLeak=0 (scripts/score-candidate15-d11.mjs:54, :59-60). Both are correct for these stored artifacts—the raw records are HTTP 200 and both frozen prompts contain no worked examples—but future code should derive and assert them from bound raw/prompt artifacts.

The raw/accounting evidence is internally consistent: 24 calls, 24 raw records, one grant, 24 reserves, 24 settlements, and the stated usage totals (AUDIT.json:8-35). The result package accurately distinguishes accounting success from scoring failure.
